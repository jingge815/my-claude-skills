# 论文总结写作指南与校对清单

本文档是 `paper-reader` 技能的阶段 4/5 作业依据：先按"各章内容要求"取材，再按"md 格式规范"落笔，最后过"校对清单"。

## 零、两条最高优先级原则

1. **自洽可读**：目标读者只读这一份总结就能完整理解论文，不需要查阅原文或任何外部资料。任何新名词、术语、缩写、机制名、策略名，**首次出现处必须先用一句话给出定义或用途，再展开使用**。写法示例：「KV 缓存（注意力计算逐 token 保存的键 Key、值 Value 中间结果，用于避免重复计算）」「提交区（Commit Zone，临时存放未写满数据块的缓冲区域）」「归约（把多个元素累加合并成一个结果）」。中文行话（如"归约""行激活""引用计数"）同样按此办理；检查器会对英文术语首现做机械校验，中文行话靠校对清单人工把关。
2. **图文与版面**：图表题注一律居中；自绘图必须通过重叠审计，并行路径用泳道布局呈现，图不过长（长宽比 0.45~2.6）。

## 一、各章内容要求

全文按 `## 一.论文概述` → `## 二.研究背景` → `## 三.研究问题` → `## 四.传统研究现状` → `## 五.本文研究方法` → `## 六.示例说明` → `## 七.实验结果` → `## 八.总结` → `## 附录` 组织。除五（方法步骤）、六（示例步骤）、七（实验分组）可用小节与附录（列表）外都用段落写法，不用标题堆砌。

### 一.论文概述（恰好 1 段，约 250~450 字）

一段话讲完全貌，信息密度要高，按以下顺序组织，句句相扣：

1. 来源：本文来自哪年、什么会议/期刊/预印本；该发表源是什么级别（如 CCF-A 顶会）、影响力如何（一句话）。
2. 背景：1~2 句大背景。
3. 问题：引出本文要解决的核心问题。
4. 已有方法：1~2 句说明已有方法的原理及不足。
5. 本文贡献：为了解决该问题，本文提出 xxx；其核心原理是什么；能带来什么能力；效果如何（关键数字）。
6. 意义：一句话点明这项工作的价值。
7. 封面引导与外链：段中用一句「本文题目、作者与发表信息如图 1 所示」式表述引导封面图；**段末**注明论文外网可访问链接，写法如「论文原文：https://arxiv.org/abs/2401.01234」。链接取自 `extract/meta.json` 的 `link_candidates`（须核实确属本文）或联网检索题目确认；确实没有就如实写「未找到公开链接」，禁止编造。

**封面图（固定动作）**：概述段之后、`## 二.研究背景` 之前，插入 `![](figs/cover.png)`（阶段 1 自动裁出的第 1 页顶部，含题目与作者信息），图题 `<p align="center">图1 论文首页封面（题目与作者信息，摘自原文第 1 页）</p>`。封面图是全文唯一允许其后无分析承接的图，其余图仍须"图前引导、图后分析"。

### 二.研究背景（1~2 段）

主要取材于论文引言与背景节。先说大的背景（领域趋势、部署形态、技术演进），要有逻辑链：每一句为下一句铺路，最终自然导向"这个问题为什么重要、为什么现在必须解决"。可配 1 张背景性原理图（如目标架构图），图前必须有文字引导，图后有承接分析。

### 三.研究问题（1~2 句概括 + 示例展开）

先用一两句话高度概括核心学术问题（一个问题，不要罗列成一堆bullet）。再结合论文的动机示例展开：多数论文有动机示例图或量化数据（如某开销占比、某场景失效），用它把抽象问题具体化——"如图 N 所示，……"，并点出问题难在哪（内在冲突、矛盾、约束）。

### 四.传统研究现状（遵从原文的分类综述 + 引用）

1. 一句总述：已有研究按什么维度分几类——**分类与内容必须遵从原文**（相关工作章/引言中的分类脉络），不得自创分类。
2. 每类一段，三要素缺一不可：**代表工作**（必须带原文引用编号，如 AttAcc[46]、NeuPIMs[21]）、**原理**（它是怎么解决本文要解决的这个问题的）、**不足**（为什么解决不好：优先用原文指出的不足，其次是从机制推出的本质局限）。只收录与本文解决**同一问题**的工作，解决其他问题的不进来。
3. 可建一张对比表（系统 × 能力维度），表数据严格按原文（如原文 Table）。
4. 结合三的动机示例说明：面对该示例，各类传统方法为什么不行——把分类不足落到具体痛点上。
5. 收尾一句：归纳共同缺口，引出本文。
6. **为第五章备料**：写完后自查一遍"不足清单"（每类至少一条本质不足），第五章讲方法时要能逐条接住；接不住的说明它不是本文针对的痛点，考虑删掉或弱化。

### 五.本文研究方法（原理 → 步骤 → 流程图）

1. 开头 1 段总述核心思想：本文 idea 是什么，为什么它能解决传统方法解决不了的问题（关键洞察，如某个冲突被什么设计化解）。行文格式不限、自然论述即可，但**内容必须与第四章咬合**：讲每个设计时，读者能看出它化解了哪类方法的哪条不足、本文的优势在哪；与第四章对不上的设计要么补现状、要么删不足，严禁"两张皮"。这条在阶段 5 校对时逐条自查（见清单 4b）。
2. 配**总体框架图**（论文现成的框架图；没有则用 draw_flow.py 自绘），图前文字引导、图后逐层解读。
3. 具体步骤允许用 `### 5.x 小节`：每个机制/模块一小节，段落式讲清"做什么—怎么做—为什么这样设计—效果数据（若有）"。步骤顺序与论文一致。
4. 若论文没有整体步骤流程图，必须自绘一张（draw_flow.py），体现输入→各阶段处理→输出的闭环。

### 六.示例说明（一个小例子贯穿全文方法，一步推出结果）

本章放在方法之后、实验之前，目的是让读者跟着一个足够小的例子把核心方法完整走一遍。写作要求：

1. **取材**：论文自带运行示例/动机示例（示例图、case study、worked example）优先，注明摘自原文；论文没有就**自构**——选一个覆盖方法主链路的最小输入（几行数据、一个小请求、一个具体张量），自构必须符合论文的设定与约束。
2. **逐步推导**：从初始输入开始，按第五章的步骤顺序一步步推到最终输出。每一步写清四件事：① 输入是什么（具体内容/数值）；② 这一步做什么变换；③ 输出是什么（具体结果）；④ 输出以什么形式存放（张量形状、位宽、数据结构、所在存储位置）。自设数值须标注「示例取值」，与论文真实数据区分开。
3. **流程图**：必配一张示例全流程图——优先 draw_flow.py 自绘（节点=步骤，节点文字或边标签写明"输入→输出"及每步数据形态）；论文有现成示例图也可直接引用并注明来源。
4. **收尾呼应**：一两句话点明这个例子体现了什么核心洞察、化解了第四章的哪条不足。

本章可按步骤用 `### 6.x 小节` 分块，也可段落式逐步写；无论哪种，步骤顺序与第五章一致，最后一步要能落到论文同类输出的结果形态上。

### 七.实验结果（目标 → 平台 → 问题 → 结果 → 分析）

1. 第 1 段：实验目标（验证什么）、平台（硬件/模拟器/数据集/模型/负载）、运行规模。
2. 第 2 段：实验要回答的具体问题（RQ 式）、对比基线及对比公平性说明（如基线如何复现）、指标。
3. 每组实验：文字先行（"如图 N 所示"），给**关键数字**，再给结论与原因分析（为什么赢/输、收益来自哪），消融实验说明每个机制的贡献。
4. 引用原文主结果图与消融图；数据多的可整理成表。实验小节可用 `### 7.x`。

### 八.总结（1 段总结 + 1 段深挖不足与改进）

1. 第 1 段（~150 字）：按原文结论章，背景→问题→方法→效果（关键数字）→意义，一气呵成。
2. 第 2 段（**关键，必须写**）：在通读全文后提炼不足与改进方向，不能只抄原文的局限段。每条要具体、可执行、能启发后续研究，至少从以下角度逐一排查（有几条写几条，不硬凑）：
   - **前提假设与限制**：方法成立依赖哪些假设（架构、负载分布、规模、同步性……），哪条在真实场景可能不成立、不成立会怎样；
   - **未考虑的因素**：被忽略的维度/开销/场景（如只测吞吐没测能耗、只在模拟器上验证、只试了某类负载）；
   - **换场景**：迁移到别的硬件/负载/领域，哪些设计要变、方法是否仍成立；
   - **与其他技术融合**：可与哪些正交技术（写明具体技术名）结合、预期解决什么、收益在哪；
   - **论文未交代或写死的关键环节**：哪些关键步骤没讲、哪些超参/策略被定死但影响很大，值得敏感性分析或重新设计。

   禁止「未来可以做更多实验」式空话；每条改进最好带一句切入思路。

### 附录（编号列表，≤10 条）

供读者日后写论文复用的素材，每条独立成文、自带出处：

- 经典结论/好词好句：原文金句可附英文原句（引号包裹）+ 中文释义，注明出处章节；
- 关键数据：最有说服力的数字对比；
- 突出本文贡献的定位句。

## 二、md 格式规范（生成器方言）

1. `# 文档标题` 有且仅有一个，居中渲染为文档题名。
2. 章节标题固定为 `## 一.论文概述` 式（中文序号+点+章名），顺序到 `## 八.总结`、`## 附录`；`### ` 仅用于方法步骤（5.x）、示例步骤（6.x）与实验小节（7.x）。
3. 每个正文段落以两个全角空格「　　」开头；不用半角空格/Tab 缩进（会被 markdown 当代码块）。
4. 插图独占一行 `![](figs/xxx.png)`，路径相对 md 文件；紧邻下一行为图题 `<p align="center">图N 题目（摘自原文 Figure M）</p>` 或 `（自绘）`——用居中标签包裹，md 预览与 docx 中均居中。
5. 表格为 GFM 管道表；表题 `<p align="center">表N 题目</p>` 独占一行放在表格上方。
6. 图表全文统一按出现顺序编号：图1、图2…，表1、表2…（与原文编号无关，题注里注明原文对应编号）；**图1 固定为论文首页封面图**（`figs/cover.png`，题注含"封面"与"摘自原文第 1 页"）。
7. 每一节的第一块内容必须是文字段落；图表前必须有文字引导（"如图 N 所示""表 N 对比了……"），图表之后要有分析承接（封面图除外）；段落开头不得直接是图表。
8. 行内标记只用 `**加粗**`；引用英文原句放引号内且只在附录出现。外网链接以纯 URL 文本写在概述段末（如「论文原文：https://…」），不加行内链接标记。
9. 图表尺寸：引用前确认裁剪完整（check_md 会查边缘残墨）、宽 ≥400px、长宽比在 0.2~6 之间。
10. 附录条目 `1.`~`10.` 编号列表；每条以结论/数据开头，出处结尾。
11. **分行规范（硬性）**：所有需要渲染为独立一行的条目行（概述段末的论文原文链接行、图题/表题行、附录各条目、以及其他连续成行的属性内容），行尾一律加**两个空格**（Markdown 硬换行）；段落与段落之间空一行。严禁把多条条目连写在一个连续段落里导致渲染粘连。

## 三、语言规范

1. 中文行文，除专有名词与技术术语（PIM、KV cache、GEMV、vLLM、QKT、SV、Commit Zone 等）外不夹英文；**术语首次出现必须给一句中文定义或用途说明**（括注释义、"X 是/指/即…"均可），先解释后使用，绝不先用后解。
2. 不在中文语句里用半角标点；数字与单位间留空格（16 GiB、2 KB、32 字节→32 B 按原文）。
3. 单句只说一件事；段落先结论后展开，段内句句有逻辑（因果、递进、对照），段间承上启下。
4. 学术、克制：不写"非常""极其"，用数字说话；不写"下面我们来看"式过渡。
5. 同一概念全文同一名词，不混用（如"提交区"不要时而写"暂存区"）。

## 四、校对清单（阶段 5 逐条过）

机械校验由 check_md.py 完成，以下为内容级人工校对项，全部通过才能生成 docx：

| # | 检查点 | 通过标准 |
| --- | --- | --- |
| 1 | 结构完整 | 九部分齐全（含「六.示例说明」）、顺序正确；概述恰好 1 段；总结不超过 2 段 |
| 2 | 发表信息与链接 | 会议/期刊/年份/级别与 PDF 或公开信息一致；概述段末有外网链接且确认归属本文（arXiv/DOI 与题目对得上，或如实标注「未找到公开链接」），无虚构 |
| 2b | 封面图 | 图1 为首页封面（题目+作者），位于概述段后、研究背景前；概述段有「如图 1 所示」式引导 |
| 3 | 数字可溯源 | 正文每个关键数字都能在原文找到（含倍数、百分比、配置参数）；换算值有说明；示例章自设数值已标注「示例取值」 |
| 4 | 机制描述准确 | 方法步骤、模块职责、数据流向与原文一致；示例推演与论文机制一致，无张冠李戴 |
| 4b | 现状↔方法咬合 | 第四章分类遵从原文且均为解决同一问题的工作，每类有原理+不足；第五章的每个设计与第四章的不足逐条对得上（哪个设计化解哪条不足、优势在哪），口径一致、无"两张皮" |
| 5 | 引用规范 | 传统现状每个类别带原文引用；图表题注注明来源 |
| 6 | 动机示例落地 | 研究问题有示例/数据支撑；传统方法的不足能对应到该示例 |
| 7 | 图表有效性 | 封面图、框架图、方法流程图、示例流程图、主实验图齐备；每图有引导文字与分析（封面图除外）；无"孤儿图" |
| 7b | 示例有效性 | 示例（论文自带或自构）贯穿方法主链路；每步输入/输出/存放形式齐全；流程图与文字一致；能一步步推出最终结果；收尾呼应第四章不足 |
| 8 | 编号与格式 | 图表从 1 连续编号；题注居中格式（`<p align="center">`）；段落「　　」开头；无中英混排、无半角标点 |
| 8b | 术语自洽 | 每个术语/缩写/机制名首现处已有定义或用途说明（check_md 已机械查英文术语，中文行话人工过一遍）；通读检验：外行读者只读本文能否顺畅理解 |
| 8c | 自绘图质量 | 重叠审计通过；并行路径用泳道呈现且与文字描述一致（说"两路"图就得是两路）；长宽比 0.45~2.6、插入 docx 后不超版心 |
| 9 | 逻辑连贯 | 段间承上启下；概述↔现状↔方法↔示例↔总结口径一致，无前后矛盾 |
| 10 | 不足与改进 | 总结第 2 段按五个角度深挖（前提假设限制/未考虑因素/换场景/技术融合/写死或未交代的关键环节），具体可执行、能启发后续研究，无空话（关键项，不可缺） |
| 11 | 附录质量 | ≤10 条；每条可独立引用；金句有出处 |
| 12 | 可读性 | 让未读过原文的读者按顺序读完即可复述：问题、洞察、方法、示例、结果、局限 |
