# 论文总结写作指南与校对清单

本文档是 `paper-reader` 技能的阶段 4/5 作业依据：先按"各章内容要求"取材，再按"md 格式规范"落笔，最后过"校对清单"。

## 零、两条最高优先级原则

1. **自洽可读**：目标读者只读这一份总结就能完整理解论文，不需要查阅原文或任何外部资料。任何新名词、术语、缩写、机制名、策略名，**首次出现处必须先用一句话给出定义或用途，再展开使用**。写法示例：「KV 缓存（注意力计算逐 token 保存的键 Key、值 Value 中间结果，用于避免重复计算）」「提交区（Commit Zone，临时存放未写满数据块的缓冲区域）」「归约（把多个元素累加合并成一个结果）」。中文行话（如"归约""行激活""引用计数"）同样按此办理；检查器会对英文术语首现做机械校验，中文行话靠校对清单人工把关。
2. **图文与版面**：图表题注一律居中；自绘图必须通过重叠审计，并行路径用泳道布局呈现，图不过长（长宽比 0.45~2.6）。

## 一、各章内容要求

全文按 `## 一.论文概述` → `## 二.研究背景` → `## 三.研究问题` → `## 四.传统研究现状` → `## 五.本文研究方法` → `## 六.实验结果` → `## 七.总结` → `## 附录` 组织。除五（可用小节）与附录（列表）外都用段落写法，不用标题堆砌。

### 一.论文概述（恰好 1 段，约 250~400 字）

一段话讲完全貌，信息密度要高，按以下顺序组织，句句相扣：

1. 来源：本文来自哪年、什么会议/期刊/预印本；该发表源是什么级别（如 CCF-A 顶会）、影响力如何（一句话）。
2. 背景：1~2 句大背景。
3. 问题：引出本文要解决的核心问题。
4. 已有方法：1~2 句说明已有方法的原理及不足。
5. 本文贡献：为了解决该问题，本文提出 xxx；其核心原理是什么；能带来什么能力；效果如何（关键数字）。
6. 意义：一句话点明这项工作的价值。

### 二.研究背景（1~2 段）

主要取材于论文引言与背景节。先说大的背景（领域趋势、部署形态、技术演进），要有逻辑链：每一句为下一句铺路，最终自然导向"这个问题为什么重要、为什么现在必须解决"。可配 1 张背景性原理图（如目标架构图），图前必须有文字引导，图后有承接分析。

### 三.研究问题（1~2 句概括 + 示例展开）

先用一两句话高度概括核心学术问题（一个问题，不要罗列成一堆bullet）。再结合论文的动机示例展开：多数论文有动机示例图或量化数据（如某开销占比、某场景失效），用它把抽象问题具体化——"如图 N 所示，……"，并点出问题难在哪（内在冲突、矛盾、约束）。

### 四.传统研究现状（分类综述 + 引用）

1. 先一句总述：已有研究按什么维度分几类。
2. 每类一段内说清：代表工作（**必须带原文引用**，如 AttAcc[46]、NeuPIMs[21]，编号用原文参考文献编号）、原理、不足。
3. 可建一张对比表（系统 × 能力维度），表数据严格按原文（如原文 Table）。
4. 结合三的动机示例说明：面对该示例，各类传统方法为什么不行——把分类不足落到具体痛点上。
5. 收尾一句：归纳共同缺口，引出本文。

### 五.本文研究方法（原理 → 步骤 → 流程图）

1. 开头 1 段总述核心思想：本文 idea 是什么，为什么它能解决传统方法解决不了的问题（关键洞察，如某个冲突被什么设计化解）。
2. 配**总体框架图**（论文现成的框架图；没有则用 draw_flow.py 自绘），图前文字引导、图后逐层解读。
3. 具体步骤允许用 `### 5.x 小节`：每个机制/模块一小节，段落式讲清"做什么—怎么做—为什么这样设计—效果数据（若有）"。步骤顺序与论文一致。
4. 若论文没有整体步骤流程图，必须自绘一张（draw_flow.py），体现输入→各阶段处理→输出的闭环。

### 六.实验结果（目标 → 平台 → 问题 → 结果 → 分析）

1. 第 1 段：实验目标（验证什么）、平台（硬件/模拟器/数据集/模型/负载）、运行规模。
2. 第 2 段：实验要回答的具体问题（RQ 式）、对比基线及对比公平性说明（如基线如何复现）、指标。
3. 每组实验：文字先行（"如图 N 所示"），给**关键数字**，再给结论与原因分析（为什么赢/输、收益来自哪），消融实验说明每个机制的贡献。
4. 引用原文主结果图与消融图；数据多的可整理成表。

### 七.总结（1 段总结 + 1 段不足与改进）

1. 第 1 段（~150 字）：按原文结论章，背景→问题→方法→效果（关键数字）→意义，一气呵成。
2. 第 2 段（**关键，必须写**）：本文还有哪些不足、哪些改进空间。取材：原文明说的局限；实验设置透露的边界（模拟器 vs 实机、代表配置、未覆盖的场景）；机制本身的代价（开销、假设）。改进方向要具体、可执行，不要空话。

### 附录（编号列表，≤10 条）

供读者日后写论文复用的素材，每条独立成文、自带出处：

- 经典结论/好词好句：原文金句可附英文原句（引号包裹）+ 中文释义，注明出处章节；
- 关键数据：最有说服力的数字对比；
- 突出本文贡献的定位句。

## 二、md 格式规范（生成器方言）

1. `# 文档标题` 有且仅有一个，居中渲染为文档题名。
2. 章节标题固定为 `## 一.论文概述` 式（中文序号+点+章名）；`### ` 仅用于方法步骤与实验小节。
3. 每个正文段落以两个全角空格「　　」开头；不用半角空格/Tab 缩进（会被 markdown 当代码块）。
4. 插图独占一行 `![](figs/xxx.png)`，路径相对 md 文件；紧邻下一行为图题 `<p align="center">图N 题目（摘自原文 Figure M）</p>` 或 `（自绘）`——用居中标签包裹，md 预览与 docx 中均居中。
5. 表格为 GFM 管道表；表题 `<p align="center">表N 题目</p>` 独占一行放在表格上方。
6. 图表全文统一按出现顺序编号：图1、图2…，表1、表2…（与原文编号无关，题注里注明原文对应编号）。
7. 每一节的第一块内容必须是文字段落；图表前必须有文字引导（"如图 N 所示""表 N 对比了……"），图表之后要有分析承接；段落开头不得直接是图表。
8. 行内标记只用 `**加粗**`；引用英文原句放引号内且只在附录出现。
9. 图表尺寸：引用前确认裁剪完整（check_md 会查边缘残墨）、宽 ≥400px、长宽比在 0.2~6 之间。
10. 附录条目 `1.`~`10.` 编号列表；每条以结论/数据开头，出处结尾。

## 三、语言规范

1. 中文行文，除专有名词与技术术语（PIM、KV cache、GEMV、vLLM、QKT、SV、Commit Zone 等）外不夹英文；**术语首次出现必须给一句中文定义或用途说明**（括注释义、"X 是/指/即…"均可），先解释后使用，绝不先用后解。
2. 不在中文语句里用半角标点；数字与单位间留空格（16 GiB、2 KB、32 字节→32 B 按原文）。
3. 单句只说一件事；段落先结论后展开，段内句句有逻辑（因果、递进、对照），段间承上启下。
4. 学术、克制：不写"非常""极其"，用数字说话；不写"下面我们来看"式过渡。
5. 同一概念全文同一名词，不混用（如"提交区"不要时而写"暂存区"）。

## 四、校对清单（阶段 5 逐条过）

机械校验由 check_md.py 完成，以下为内容级人工校对项，全部通过才能生成 docx：

| # | 检查点 | 通过标准 |
| --- | --- | --- |
| 1 | 结构完整 | 八章齐全、顺序正确；概述恰好 1 段；总结不超过 2 段 |
| 2 | 发表信息准确 | 会议/期刊/年份/级别与 PDF 或公开信息一致，无虚构 |
| 3 | 数字可溯源 | 正文每个关键数字都能在原文找到（含倍数、百分比、配置参数）；换算值有说明 |
| 4 | 机制描述准确 | 方法步骤、模块职责、数据流向与原文一致；无张冠李戴 |
| 5 | 引用规范 | 传统现状每个类别带原文引用；图表题注注明来源 |
| 6 | 动机示例落地 | 研究问题有示例/数据支撑；传统方法的不足能对应到该示例 |
| 7 | 图表有效性 | 框架图、流程图、主实验图齐备；每图有引导文字与分析；无"孤儿图" |
| 8 | 编号与格式 | 图表从 1 连续编号；题注居中格式（`<p align="center">`）；段落「　　」开头；无中英混排、无半角标点 |
| 8b | 术语自洽 | 每个术语/缩写/机制名首现处已有定义或用途说明（check_md 已机械查英文术语，中文行话人工过一遍）；通读检验：外行读者只读本文能否顺畅理解 |
| 8c | 自绘图质量 | 重叠审计通过；并行路径用泳道呈现且与文字描述一致（说"两路"图就得是两路）；长宽比 0.45~2.6、插入 docx 后不超版心 |
| 9 | 逻辑连贯 | 段间承上启下；概述↔各章↔总结口径一致，无前后矛盾 |
| 10 | 不足与改进 | 总结第 2 段确实提炼了不足与可执行的改进方向（关键项，不可缺） |
| 11 | 附录质量 | ≤10 条；每条可独立引用；金句有出处 |
| 12 | 可读性 | 让未读过原文的读者按顺序读完即可复述：问题、洞察、方法、结果、局限 |
