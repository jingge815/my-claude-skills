# 论文精读总结工具（paper-reader）

把一篇论文 PDF 变成一份读者能快速理解论文全貌的中文总结：先深读论文，再产出同一目录下的 `summary.md` 与 `summary.docx`（英文文件名），总结自洽可读（术语首现即解释，只读本文即可理解全文），并嵌入原文关键图表（无现成图时自绘，自绘图经重叠审计）。

## 工作流程

按顺序执行五个阶段，每个阶段都有明确产物；上一阶段产物是下一阶段的输入。

### 阶段 0：环境与目录约定

- 本技能自带虚拟环境：`PY=/home/jgfeng/.claude/skills/paper-reader/.venv/bin/python`，脚本在 `SKILL_DIR=/home/jgfeng/.claude/skills/paper-reader/scripts/`。若 `.venv` 缺失，按 `requirements.txt` 用 uv 重建。
- 工作目录：在 PDF 所在目录下创建 `<PDF文件名去后缀>_summary/`，所有产物放其中。交付文件用固定英文名，不用中文文件名：

```
<PDF名>_summary/
├── extract/          # 阶段1产物：text.md、pages/、figures/、figures.json、meta.json
├── figs/             # 总结实际引用的图（从 extract/figures/ 复制，自绘图也放这里）
├── summary.md        # 最终交付 1（论文总结）
├── summary.docx      # 最终交付 2
└── *.json            # 自绘图（draw_flow.py）的 spec 文件
```

### 阶段 1：提取论文内容

```bash
$PY $SKILL_DIR/extract_pdf.py <论文.pdf> --out <工作目录>
```

产出 `extract/text.md`（带 `<!-- page N -->` 页码标记的全文）、每页 110 dpi 预览图、按图注自动裁剪的 200 dpi 图表 PNG 及 `figures.json`（含每图的 id、页码、原文图注、宽高比）。

- 若提示"可提取文字很少"（扫描版）：不读 text.md，改为用 Read 工具逐段查看 `extract/pages/pageNN.png` 通读论文。
- `figures.json` 中 `crop: null` 的条目是定位失败的兜底整页图，引用前必须人工确认裁剪范围。

### 阶段 2：深读论文

通读 `extract/text.md` 全文（长文分段读完，不许跳读），并用 Read 工具直接读 PDF 的关键页（图表所在页）核对图的理解。读完后必须能回答（写总结前自检）：

1. 研究背景是什么，逻辑链如何导向研究问题；
2. 核心研究问题一两句话是什么；论文的动机示例/数据（通常有示例图）说明什么缺口；
3. 已有研究分几类，每类的原理与不足（对应哪些参考文献）；
4. 本文的 idea 是什么，为什么它能解决之前解决不了的问题（关键洞察）；
5. 具体实施步骤（模块划分、算法/机制流程）；
6. 实验目标、平台、负载、基线、指标、结果数字与结论分析；
7. 原文的结论、局限与可改进空间。

**发表信息**：从 PDF 首页/页眉/元数据确认会议或期刊与年份；级别与影响力（如 CCF 分级、录用率）按公认常识描述，拿不准时联网核实，**禁止编造**；确无会议标注（如 arXiv 预印本）就如实写预印本。

### 阶段 3：选图与备图

把总结要用的原文图从 `extract/figures/` 复制到 `figs/`（保留 figN.png/tabN.png 原名），自绘图经 `draw_flow.py` 生成后也输出到 `figs/`：

```bash
cp extract/figures/fig5.png figs/fig5.png
$PY $SKILL_DIR/draw_flow.py <spec.json> figs/flow_xxx.png   # 论文没有现成流程图/框架图时
```

- 必选：总体方法框架图、方法步骤流程图（论文没有就自绘）、主实验结果图；按内容需要加动机示例图、对比表、消融图。
- `draw_flow.py` 的 spec 用 JSON 描述节点与边（可带标签），中文直接可写；**并行路径/双路结构必须用泳道布局**（定义 `lanes` 列出路径名，节点标 `lane`，公共节点标 `span: true`），让"几路"在图上一目了然。脚本自带重叠审计（节点×节点、标签×节点、标签×标签、文字越界、画布过长），审计不过会报错退出——缩短标签文字或调整布局后重画，不许跳过。
- 自绘图必须准确反映论文机制，宁可简单不可画错；高度尽量压缩（优先双列泳道而非单列长链），长宽比落在 0.45~2.6 为宜。

### 阶段 4：撰写 summary.md

**先读 `references/writing-guide.md`**，按其中各章内容要求与 md 格式规范撰写。两条最高优先级要求：

- **自洽可读**：读者只读这一份总结就能完整理解论文，不需要查阅任何外部材料。任何新名词、术语、缩写、策略名在**首次出现处**就用一句话给出定义或用途（如「KV 缓存（注意力计算逐 token 保存的键值中间结果）」「提交区（Commit Zone）暂存……」），先解释再使用；中文行话同样要自明（如「归约（把多个元素累加合并成一个结果）」）。
- 段落间承上启下、段内句句有逻辑；除专有名词外不夹英文。

格式要点（docx 生成器只认这个方言）：

| 元素 | 写法 |
| --- | --- |
| 文档标题 | `# 《中文译名》论文总结`（全文唯一） |
| 章节 | `## 一.论文概述` … `## 七.总结`、`## 附录`，顺序固定 |
| 小节标题 | `### 5.1 xxx`（仅方法步骤、部分实验等允许用） |
| 正文段落 | 每段以两个全角空格「　　」开头；不用 4 空格/Tab 缩进 |
| 插图 | 独占一行 `![](figs/xxx.png)`，下一行图题（居中标签包裹，见下） |
| 图题 | `<p align="center">图N 题目（摘自原文 Figure M / 自绘）</p>`，md 预览居中，docx 中自动居中 |
| 表格 | GFM 管道表；表题行 `<p align="center">表N 题目</p>` 在表格上方 |
| 附录条目 | `1.` 起的编号列表，不超过 10 条 |
| 强调 | 仅 `**加粗**`，不用其他行内标记 |

图表在全文按出现顺序统一重新编号（图1、图2…，表1、表2…），题注注明摘自原文哪个图或"自绘"。

### 阶段 5：校对，全部通过后生成 docx

1. 机械校验，**错误必须清零、警告必须逐条处理**（确属合理的可放行并说明理由）：

```bash
$PY $SKILL_DIR/check_md.py summary.md --extract extract
```

覆盖：八章结构完整且顺序正确、概述恰 1 段、总结含不足与改进、图/表题注齐全且居中格式正确、编号连续、图片文件存在且清晰度/长宽比/裁剪完整性达标、每节开头是文字段落、段落全角空格开头、中英混排与半角标点、附录不超 10 条、**术语首现解释**（英文术语第一次出现处须有中文定义线索，保证自洽可读）、**数字溯源**（正文数字逐个到 text.md 里查，防止写错或编造）。

2. 内容级校对，对照 `references/writing-guide.md` 末尾的校对清单逐条自查：事实与原文一致（数字、机制、归属）、术语解释是否通俗准确、段落间承上启下、每图有"如图 N 所示"式的文字引导与分析、自绘图是否体现了并行路径等结构、总结确实提炼了不足与改进（关键项）。
3. 生成并验证 docx：

```bash
$PY $SKILL_DIR/build_docx.py summary.md
```

生成后核对输出统计（插图数、表格数与 md 一致）。

## 排版效果（docx）

A4、页边距 2.5 cm；标题黑体三号居中，节标题黑体四号；正文宋体/Times New Roman 小四、1.5 倍行距、首行缩进 2 字符、两端对齐；插图按版心宽 16 cm 自适应（超高按 19 cm 限高缩放）、居中；图题表题居中加粗五号；表格 Table Grid、表头浅灰底。

## 硬性规则

1. 总结中的每一个数字、每一个机制描述都必须来自原文；换算值写明换算关系。
2. 发表信息（会议/期刊、年份、级别）不确定就核实或如实标注，禁止虚构。
3. **只读总结即可理解全文**：任何术语、缩写、策略名首次出现处先给定义/用途再使用；正文不依赖任何外部背景。
4. 不中英混杂：除专有名词与技术术语（如 PIM、KV cache、vLLM），一律中文表述。
5. 图表题注一律居中（md 用 `<p align="center">` 包裹，docx 自动居中）；图表编号连续、注明来源。
6. 自绘图必须通过 draw_flow.py 的重叠审计；并行结构用泳道布局呈现；图不过长（长宽比 0.45~2.6）。
7. 校验未通过（错误非零）不得生成 docx；生成 docx 前必须完成内容级校对。
8. 不修改论文 PDF 与 extract/ 下的原始提取产物；figs/、summary.md 与 summary.docx 是唯一交付物，交付文件名用英文。
