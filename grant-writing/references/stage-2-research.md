# 阶段 2：文献与资料调研，构建资料库，需求导向精读

**执行者**：调研员（1 个，可按来源拆 2–3 个并行）负责检索下载与卡片；精读员（N 个并行，每片 ≤15 篇）负责拟引用论文的精读。**主 agent**：派发、收尾清点、核对门槛。
**输入**：阶段 1 的调研大纲（含槽位号）。
**落盘**：`grant-<项目简称>/02-资料库/`，内含 `pdfs/`、`texts/`、`index.md`、`阅读记录.md`、`精读记录.md`（合并自各分片）、`待补全文.md`、`背景数字核验.md`。

## 检索范围

- 学术文献：该领域的顶会、顶刊、综述、学位论文。
- 技术资料：GitHub 仓库、技术标准、行业白皮书。
- 政策依据：国家或部委规划、重大专项指南。只摘能核对原文的表述。

## 调研员怎么做

1. 先调用 `claude-skills-research`，把阶段 1 的调研槽位作为调研问题交给它：学术文献的检索、来源准入、原文核验、正式引用格式都按该技能执行。本技能不另写一套检索规则，也不改那个技能的文件。
2. 在此基础上补两类它不覆盖的材料：技术资料（GitHub 仓库、技术标准、行业白皮书）和政策依据（只摘能核对原文的表述）。
3. 论文与关键资料必须落到本地：正文拟引用的论文一律下载 PDF 全文入库到 `pdfs/`，并用 pymupdf 抽取全文文本到 `texts/`（精读员读文本、核对时回 PDF 页码）。仓库记录 README 与关键目录结构。
4. 每份资料在 `index.md` 配一张卡片：编号、文件路径、来源链接、访问日期、出处与年份、CCF/权威期刊档次、一句话说明它支撑大纲的哪个槽位号。
5. PDF 下不了时不降级、不绕过——把「题名 + 出处 + 需要它支撑的论断」整理进 `待补全文.md` 并告知用户，由用户获取后放入资料库再继续；摘要、检索页、二手转述都不能顶替全文进入写作。
6. 用户若指定了论文库或资料目录（"只用某目录内的论文"这类硬约束），检索范围不得超出该约束。
7. 引用任何一篇之前，打开原文核对题名、作者、年份、venue。搜不到、打不开、对不上的，丢弃。
8. **背景数字核验**：研究背景拟用的每个数字（市场规模、增速、占比、利用率）单独落 `背景数字核验.md`：数字、原文出处（论文页码 / 官网页面 / 报告名称）、访问日期、口径说明、核验结论（成立 / 需收紧 / 弃用）。新闻、博客、二手综述转述的数字不得直接引用——实测出现过转述比例在原始调查中不存在的情况；核对发现原文无此数据时立即弃用，不换一个相近数字继续写。
9. 每篇入库论文都要在 `阅读记录.md` 落一条关键点总结（研究对象、方法原理一句话、关键结果、与本项目的相关点、所属槽位号）。这是全部入库论文的最低要求，不顶替精读。

## 精读员怎么做：需求导向精读

精读的对象是「正文拟引用的论文」。精读记录**不是论文摘要的复述**，而是围绕申请书需要什么的提炼。每篇一条，固定字段：

```
### 精读 [编号] 〈题名〉（〈出处 年份〉）
- **服务于**：〈槽位号〉+〈申请书中拟支撑的具体论断，一句话〉。例：R3-不足「静态并行计划与动态负载脱节」；或 BG-需求数字「集群平均利用率 52%」。
- **核心内容（≤150 字，用自己的话）**：它针对什么问题、靠什么核心机制成立、做到了什么程度。不抄摘要句。
- **可引用事实**：〈数字或结论〉——〈原文页码/章节〉。每条都要能翻到。
- **总体原理与前提假设**：这类方法成立依赖的前提是什么（供研究现状写「然而上述工作均以……为前提」）。
- **原理层局限**：该原理决定了什么做不到（「该原理决定了……」一句话）；区分范围限定 / 资源限制 / 语义假设三种性质，用「结论只对……成立」措辞。
- **归类**：路线〈R?〉；归类依据回指原文哪句（它验证什么对象、保证在什么时机产生）。
- **不引用会怎样**：〈一句话〉。若答「无影响」，该论文不进正文引用，只在阅读记录保留。
```

**防抄摘要校验**（精读员自查 + 主 agent 抽查）：

- 「核心内容」与 `texts/` 中 Abstract 段做 8-gram 重合检查，重合 >30% 退回重写。写法提示：先合上论文，用一句话说「它为什么能解决/为什么解决不了本项目关心的问题」，再打开论文填数字和页码。
- 「可引用事实」的每一条数字，主 agent 抽查时打开 PDF 对应页核对；对不上的整条作废，不得「大概是对的」放过。

**分片与合并**：按 `index.md` 编号顺序切片，每片 ≤15 篇，精读员写 `精读记录_partK.md`；调研员或主 agent 在收尾时按编号顺序合并为 `精读记录.md`，并写头部统计（覆盖篇数、按槽位号分布、归类存疑篇）。

## 文献门槛（进入阶段 3 前核验，硬性）

- **数量**：下载入库的论文全文必须超过 80 篇（至少 81 篇）。不足先补检索。
- **档次**：遴选优先 CCF 推荐国际会议/期刊（A、B、C 类）与中文权威期刊（《软件学报》《计算机学报》《自动化学报》《中国科学》相关辑）。填不满时才允许放宽，放宽的每一篇在卡片标注档次与放宽理由，不得用低水平会议、期刊充数。
- **时效**：优先近 5 年。作为分类或方法根基的经典开创性工作不受年限限制，但数量控制在少数，卡片注明奠基地位。
- **逐篇记录**：全部入库论文有阅读记录；拟引用论文有需求导向精读记录，且「不引用会怎样」不为空。
- **收尾清点**：`index.md` 末尾落一段统计：入库总篇数、CCF/权威期刊篇数与占比、近 5 年篇数与占比、精读篇数、`待补全文.md` 条目数。不达标先补齐。

## 主 agent 核对

- `index.md` 统计段存在且达标；`pdfs/` 文件数 ≥ 统计篇数。
- `精读记录.md` 每条七字段齐全（Grep 字段名计数 = 精读篇数）。
- 随机抽 3 篇：打开 `pdfs/` 对应 PDF 的指定页核对「可引用事实」。
- `待补全文.md` 为空，或剩余条目已经用户书面豁免。
