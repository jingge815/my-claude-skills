# 多 agent 编排协议

派任何子 agent 之前读完本文件。本文件回答四个问题：主 agent 做什么不做什么、有哪些子 agent 角色、子 agent 的 brief 怎么写、交接与异常怎么处理。

## 1. 为什么要编排

一份申请书的流程文档（本目录 `references/`）加上资料库、论证、正文、图、校对记录，总量远超单个对话能稳定持有的上下文。把全过程塞进主对话的直接后果是：写到研究内容时忘了研究现状的分类口径，画图时忘了正文里的术语，校对时凭印象打勾。所以：

- **主对话只持有「状态」不持有「内容」**：状态 = 当前阶段、各交接物路径、门禁结果、遗留问题清单。内容全部在文件里。
- **每个子 agent 只拿到它这一步需要的文件路径和规范片段**，拿不到的它就不该知道；子 agent 的全部产出落盘，回给主 agent 的只有 ≤300 字摘要加问题清单。
- **子 agent 之间不直接对话**，后序子 agent 以前序子 agent 的落盘文件为输入。主 agent 不转述子 agent 的内容（转述必然失真），只转交文件路径。

## 2. 主 agent 的职责边界

**要做**：

1. 开工时确定项目简称，创建 `grant-<简称>/` 工作目录，向用户确认主题、素材、基金类别、模板四件事。
2. 每个阶段开始前读对应的 `references/stage-N-*.md`，把其中的硬约束提炼成子 agent brief。
3. 用 Agent 工具派子 agent；可并行的（三案竞标、精读分片、多图、多路校对）在同一条消息里同时派。
4. 子 agent 回报后：核对交接物文件存在；跑该阶段的脚本（有则跑）；抽查 1–2 处关键内容回原文核对（不全文读）。
5. 门禁通过 → 向用户做 ≤200 字的阶段汇报并询问确认（阶段 1、3、4 需要用户确认，阶段 2、5、6 只汇报）；门禁不通过 → 按 §6 异常处理。
6. 记录状态：在 `06-质量自检.md` 顶部维护「阶段进度表」（阶段、执行者、交接物、门禁结果、日期）。

**不做**：

- 不亲自写、改、润色申请书的任何段落（发现问题写进返工单交写手）。
- 不亲自画图、不改图坐标、不亲自调 spec（写图需求交画图员）。
- 不亲自逐句校对（派校对员）。
- 不亲自跑 build 脚本以外的手工 docx 编辑（docx 永远由脚本从 md 生成）。
- 不把子 agent 的完整输出读进上下文；需要核查时用 Grep/Read 读指定文件的指定行段。

## 3. 子 agent 角色

| 角色 | 阶段 | 并行度 | 输入 | 输出 | 回报 |
| --- | --- | --- | --- | --- | --- |
| 拆解员 | 1 | 1 | 用户主题与素材 | `01-调研大纲.md` | 七槽位是否齐全、闭环句式、待用户确认事项 |
| 调研员 | 2 | 1（可按来源拆 2–3） | 调研大纲 | `02-资料库/pdfs/`、`texts/`、`index.md`、`待补全文.md`、`背景数字核验.md` | 入库篇数、CCF/近 5 年占比、待补清单 |
| 精读员 | 2 | N（每片 ≤15 篇） | 一片论文清单 + 调研大纲七槽位 | `02-资料库/精读记录_partK.md` | 本片完成篇数、归类存疑篇、查无出处的数字 |
| 竞标写手 | 3 | 3（互不通气） | 同一输入包：调研大纲 + index.md + 阅读记录 + 用户素材要点 | `03-竞标-案A/B/C.md` | 五槽位是否写满、回指资料库编号数 |
| 论证员 | 3 | 1 | 基准案 + 精读记录 + 阅读记录 | `03-调研论证.md` | 六章齐全、对照表是否画出、归类修正项 |
| 格式员 | 4 | 1 | 用户模板或四问答复 | `04-格式说明.md` | 章节层级、字数、图表位置是否可执行 |
| 提炼员 | 5a | 1 | 用户源码/技术文档 | `05-已有工作提炼.md` | 模块数、每模块四件事齐全数、「不纳入」项 |
| 写手 | 5b、7 | 1 | 论证 + 格式说明 + 提炼 + 精读记录 + 规范三文件 | `05-申请书.md`、`05-口径表.md`、图规格清单 | 各章完成情况、图位清单、待用户确认项 |
| 画图员 | 5c | 每图 1 个（并行） | 单张图规格 + 正文相关段落 | `figs/figN.spec.json`、`figs/figN.png`、`figs/figN.png.audit.txt` | 审计结果、视觉自检轮次、与正文的术语差异 |
| 审查员 | 6 | 1 | `05-申请书.md` + 规范三文件 + 资料库索引 | `06-质量自检.md` 的九条验证点部分 | 九条逐条通过/不通过 + 证据位置 |
| 校对员 | 6、7 | ≥2（独立、brief 不同） | `05-申请书.md` | `06-校对问题单_第K路.md` | 发现数、按类型分布、严重项前 5 条 |
| 构建员 | 6b、7 | 1 | `05-申请书.md` + `figs/` | `05-申请书.docx` + 脚本输出 | build/verify 退出码、警告数 |

同一子 agent 不兼两职：写手不校对自己的稿，画图员不审自己的图（视觉自检除外，那是画图员的职责之一），审查员不修稿。

## 4. 子 agent brief 模板

每份 brief 固定六段，缺一段不派。brief 是子 agent 能看到的全部上下，写具体、给绝对路径、给可检查的完成条件。

```
【角色与目标】你是〈角色〉。本次只做〈一句话目标〉，不做其他阶段的事。
【必读文件】按顺序读：1) 〈规范文件绝对路径〉（硬约束全在里面）；2) 〈输入文件绝对路径〉…。
    规范文件只读与本次相关的章节：〈章节名〉；不要通读本目录其他文件。
【输入事实】〈只列本阶段需要的事实：项目简称、工作目录、口径表路径、已确认的分类与难点条数等〉。
【输出文件】写到〈绝对路径〉。格式要求：〈结构、字段、字数〉。不要写到别处，不要修改输入文件。
【硬约束】逐条列：〈规范文件里的 MUST，编号引用〉；〈不得编造、不得凭摘要、不得改口径〉；〈脚本命令与退出码要求〉。
【自检与回报】完成前自检：〈清单〉。回报格式（≤300 字）：完成情况 / 交接物路径 / 门禁结果（脚本输出摘要）/ 问题清单（每条：位置 + 问题 + 建议）/ 需要主 agent 或用户决策的事项。
```

写 brief 的三条纪律：

- **给文件不给结论。** 把规范文件和输入文件交给子 agent，让它自己读；不要在 brief 里替它总结「现状应该分五类」——主 agent 一旦给了结论，子 agent 就只会确认它。
- **完成条件可机械检查。** 「写好研究现状」不是完成条件；「研究现状含显式分类句、路线节数 = N、每节有『然而上述工作均以…为前提，该原理决定了…』句、`check_md.py` C12 零警告」才是。
- **子 agent 不知道的不编。** brief 里要明说「输入文件里没有的事实，写进问题清单回报，不要自行补写」。

## 5. 交接物协议

- 交接物 = 文件，不是回报文字。回报只是索引。
- 每个交接物头部有一行元信息：`> 版本 vN-YYYYMMDD | 执行者:〈角色〉| 输入:〈文件列表〉| 门禁:〈通过/未过 + 脚本摘要〉`。
- 后序子 agent 读前序交接物时只读它需要的章节；brief 里指明章节名或行段。
- 主 agent 核对交接物：文件存在、头部元信息齐全、脚本退出码为 0、抽查一处内容回原文对得上。四项任一不满足即返工。
- 版本：每轮返工覆盖同一文件并在头部递增版本号；旧版本不保留在交付目录（需要追溯时看 `06-质量自检.md` 的轮次记录）。

## 6. 异常处理

| 情形 | 处置 |
| --- | --- |
| 子 agent 回报「输入不足、无法继续」 | 这是正确行为。主 agent 把问题转给用户或补齐输入后再派；不让子 agent 猜。 |
| 子 agent 产出不达标（门禁脚本非 0、槽位缺失） | 返工单：把脚本输出 + 缺失项原文贴回同一子 agent（SendMessage 续接其上下文）让它修；最多 2 轮。2 轮仍不达标换新子 agent 并改 brief（更窄的范围、更具体的完成条件），不改标准。 |
| 子 agent 超时或无回报 | 用 TaskStop 终止；检查已落盘的部分产物决定是续接还是重派；不把半成品带进下一阶段。 |
| 子 agent 之间产物冲突（如精读员 A 与 B 对同一篇论文归类不同） | 以回原文核对为准：派一个精读员（或主 agent 抽查）打开 PDF 对应页核对，裁定后写入 `index.md` 卡片的归类依据，其他处同步。 |
| 子 agent 把规范外的内容写进了交接物（编造数字、无出处断言） | 该条删除并在 `06-质量自检.md` 记录「已剔除 + 原因」；不留着让下一棒判断。 |
| 用户中途改主题、改口径、改分类 | 回到受影响的最前一个阶段重派（改分类回阶段 3，改口径回 5b 的口径表），不就地打补丁；在阶段进度表记录变更来源。 |
| 迭代到 20 轮仍有未过项 | 停止迭代，如实向用户报告已通过项、剩余项、卡住原因；不降低标准，不静默交付。 |

## 7. 并行策略

- **三案竞标**：三个竞标写手在同一条消息里同时派，brief 除「案号」外逐字相同；三者都拿不到彼此的输出路径。
- **精读分片**：按 `index.md` 编号顺序切片，每片 ≤15 篇，每片一个精读员；分片数 ≤6，超过则分两批。
- **画图**：每张图一个画图员并行；共享同一个 `scripts/draw_figure.py`，各写各的 `figs/figN.*`，互不写对方文件。
- **校对**：≥2 路同时派，brief 不同：第 1 路侧重语法、搭配、指代、标点、数字格式；第 2 路侧重逻辑连接、术语一致、段落首句点题、口径一致。两路都只出问题单不改稿。
- **检索与提炼**互不依赖，可同时派（阶段 2 与 5a）。

## 8. 主 agent 的阶段汇报模板

每个阶段门禁通过后给用户：

```
阶段 N 〈名称〉完成（〈日期〉）。
交接物：〈路径列表〉
门禁：〈脚本退出码 / 人工核对项〉
需要你确认：〈事项，没有则写「无」〉
下一步：阶段 N+1 〈名称〉，执行者〈角色〉。
```

阶段 6 首次交付时额外附：九条验证点结果表、校对轮次与发现/修复数、遗留事项、docx 的 verify 摘要、提醒用户用 Word 打开终验图片显示。
