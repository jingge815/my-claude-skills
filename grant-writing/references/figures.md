# 专职绘图规范（画图员）

图是画出来的，不是拼出来的。最终稿里禁止 ASCII 框图、禁止用代码块冒充图——ASCII 图在 Word 里对不齐、字体不一、无法缩放，评审看到的就是一团乱码。每张图由画图员子 agent 先生成 PNG，经机械审计 + 视觉自检至少两轮通过后，写手才嵌入。

## 流程（每张图固定五步，不得跳步）

```
写手图规格 ──► ① 画图员写 figs/figN.spec.json
           ──► ② 跑 draw_figure.py（内置重叠审计，任一 FAIL 即退出 1）
           ──► ③ 用 Read 工具打开 PNG，按「视觉自检清单」逐项看
           ──► ④ 不通过 → 改 spec → 回到 ②；通过 → 再跑一轮 ③ 作为第二人视角复核
           ──► ⑤ 回报写手嵌入；写手核对图内术语与正文逐字一致
```

- **先生成，后嵌入**：写手在正文只留 `![](figs/figN.png)` 与图规格注释，不自己画；画图员不改正文。
- **每张图至少两轮自检**：第 1 轮刚画完就看，第 2 轮隔一个动作（例如画完别的图回来）再看——第 1 轮容易看见自己想看见的。两轮都记在 `figs/figN.png.audit.txt` 末尾（`视觉自检 第K轮: 通过/发现问题`）。
- **审计失败不许绕**：`draw_figure.py` 退出码非 0 时不得嵌入，不得手工改 PNG，不得缩小字号硬塞。改 spec（减节点、缩短文字、换布局、拆成两张图）。
- **多图并行**：每张图一个画图员，同一条消息里同时派；各写各的 `figs/figN.*`，共享同一个脚本。

## 画图员 brief 模板

```
【角色与目标】你是画图员。只画图 figN，不写、不改正文。
【必读文件】1) ~/.claude/skills/grant-writing/references/figures.md（本文件）；
            2) ~/.claude/skills/grant-writing/scripts/draw_figure.py 头部 docstring（spec 格式与审计项）；
            3) 图规格：<grant目录>/05-申请书.md 的 L<起>–L<止>（<!-- 图规格 figN --> 块）；
            4) 术语来源：<grant目录>/05-申请书.md 的 L<起>–L<止>（研究内容总起段 / 该项第 3 段 / 模块标题）。
【输出文件】<grant目录>/figs/figN.spec.json、figN.png、figN.png.audit.txt（追加视觉自检两轮记录）。不写别处。
【命令】PY=~/.claude/skills/grant-writing/.venv/bin/python；$PY ~/.claude/skills/grant-writing/scripts/draw_figure.py figs/figN.spec.json figs/figN.png；退出码必须为 0。
【硬约束】图内每个框的文字、机制名、模块编号与术语来源逐字一致；每框 ≤ 20 字；一张图 ≤ 6 个分组、每分组 ≤ 4 项；不设图内大标题；不出现正文没有的箭头；正文提到的每条流向都有箭头。
【自检与回报】按视觉自检清单两轮；回报（≤200 字）：审计结果 / 两轮视觉自检结论 / 图内术语与正文的差异（若有）/ W×H。
```

## 图规格（写手写给画图员）

写手在正文图位写 HTML 注释块（见 `stage-5-writing.md` 图位约定），内容是：类型、布局、标题、顶带（输入/科学问题）、分组（研究内容 N → 模块列表）、边（含标签）、底带（验证载体）、术语来源的行段。画图员把它转成脚本的 JSON spec，不自行增删框。

### 两类图

| 类型 | 用在哪 | 画什么 |
| --- | --- | --- |
| `framework` | 图 1 总体研究框架；每项研究内容 1 张总体架构图 | 分组容器 = 研究内容（标题条带「研究内容 N + 名称」，可带「编译期/运行期」角标），组内条目 = 模块（编号 + 机制名），底部紫色「产出：…」条；顶带 = 科学问题/输入；底带 = 验证载体；组间箭头 = 「前项产出 → 后项消费」并带产出标签 |
| `flow` | 技术路线图、方法流程图 | 泳道（两条并行路径）或层级（先…再…后…）布局的节点与边；节点文字 = 机制名 + 作用对象 |

### 版面与字号（为什么是这些数）

画布逻辑宽固定 **1400 px**，放进 16 cm 版心时 3.09 px/pt：节点字 28 px ≈ **9.1 pt**、标签 22 px ≈ **7.1 pt**、标题条 32 px ≈ 10.4 pt——这是正文可读的下限。画布再宽、同样字号印出来就更小；所以**不要靠缩字号硬塞内容**，要减节点、减分组、拆图。

布局默认：分组 ≤4 用 `row`（4 组自动排成 2×2，`per_row` 可改），5–6 组用 `column`（图会偏高，长宽比 <0.9 时脚本警告，此时拆成总图 + 子图）。目标长宽比 0.9–2.2。

### spec 字段速查（以 `draw_figure.py` docstring 为准）

```jsonc
{
  "type": "framework",
  "title": "异构融合智能系统总体研究框架",      // show_title 默认 false：图注在文档里，图内不重复
  "layout": "row",                             // row（≤4 组，默认 2×2）| column（5–6 组）；"per_row": 3 可改
  "bands": {"name": "科学问题与需求输入", "items": ["多厂商异构算力", "集群与云边端动态负载", "端侧资源受限"]},
  "groups": [
    {"id": "g1", "title": "研究内容1  等价映射与符号成本", "tag": "编译期",     // 标题 ≤ 15 字，tag 可省
     "items": ["1.1 统一中间表示与语义契约", "1.2 两层编译与等价锚点", "1.3 符号系数成本模型与两点接入"],
     "output": "统一IR + 符号成本系数"}                                           // 产出条，可省
  ],
  "edges": [["g1", "g2", "成本系数"], ["g2", "g3", "执行流显式化"], ["g1", "g4", "内存预算"], ["g1", "footer", "软件栈原型"]],
  "footer": {"name": "验证载体", "items": ["软件栈原型", "集群调度原型", "协同框架原型", "端侧算子库原型"]},
  "forbidden_variants": ["系统栈", "平台"]      // 可选：这些词出现在任何框里即审计 FAIL
}
```

边路由脚本自动决定：同行相邻走组间空隙（标签在线上方）；跨行走行间空隙（标签在水平段上，多条自动错开）；同行跳过走顶部专用 lane；非末行分组 → 验证载体走左/右页边 lane（标签逐字竖排）。这些 lane 都是预留的空白区，所以正常情况不会穿框；审计报 `edge-through-node` 时，优先调整分组顺序、删掉不必要的边，或拆图。

## 审计项（脚本自动，任一 FAIL 退出 1）

`node×node`（框与框不相交）· `group-containment`（条目在容器内，容器互不相交）· `label×node` / `label×label` / `label×edge`（边标签不压框、不压其他标签、不压其他边）· `text-in-box`（文字实际渲染宽高都在框内）· `text-in-canvas`（全部在画布内且留边）· `edge-through-node`（箭头不穿过无关的框）· `font-size`（节点文字 ≥28px、标签 ≥22px 逻辑像素，对应 16cm 放置时 9pt / 7pt）· `min-gap`（相邻框间距 ≥6px，贴边也算失败）· `term-consistency`（禁用变体词不出现）。

## 视觉自检清单（画图员用 Read 看 PNG，逐项打勾，任一项不过就改 spec）

1. **文字与框**：每个框里的文字四边都不贴框线（≥ 8px 视觉留白），没有文字被框线切过，没有一行文字折成孤字。
2. **文字与文字**：任意两段文字不相交、不叠压；边标签压在线上时有白底，线不穿字。
3. **箭头与框**：箭头从框边出发、到框边结束，不从框中间穿出，不穿过第三个框；箭头尖不埋进框里。
4. **箭头与标签**：每条有标签的边，标签紧贴自己的边；不出现标签离边太远、分不清属于哪条边的情况。
5. **分组容器**：研究内容 N 的标题条带与条目区有颜色区分；条目不出容器；容器之间的间距一致。
6. **层级可读**：分组 > 条目 > 标签三级字号有肉眼可见的差异；标题条带文字加粗。
7. **术语一致**：逐个框核对——机制名、模块编号、研究内容编号与正文术语来源逐字一致；正文没有的词不出现。
8. **信息完整**：顶带有输入/科学问题，底带有验证载体，组间边有产出标签；总图里每个模块都能在子图里找到。
9. **无多余元素**：没有图内大标题（图注在文档里）、没有水印、没有测试用的占位文字。
10. **整体版面**：长宽比在 0.9–2.2 之间（太长会占满整页，太扁缩进文档后字太小）；按 16cm 宽放进 Word 后，最小的字（标签 22px ≈ 7pt）仍可读。
11. **放大看细节**：把 Read 工具返回的图局部放大（或用 PIL 裁一块放大后再 Read）看文字边缘是否清晰、有没有半截字。

## 嵌入与 docx（写手与构建员）

- md：`![](figs/figN.png)` 独占一行，紧接一行 `图N 〈题名〉`，再空行；正文在前一段末有「如图 N 所示」。
- docx：`build_docx.py` 把图片段落设为自动行距（固定值行距会让图在 Word 里「消失」成一条缝）、宽度按版心等比缩放（≤16cm）、居中；`verify_docx.py` V03/V04/V13 断言行距、尺寸、有效 DPI ≥110。
- 图像素宽 =1400（逻辑画布 1400 × 2 倍超采样渲染后缩回），16cm 放置时 ≈222 DPI，远高于 110 DPI 下限；`check_md.py` C18 与 `verify_docx.py` V13 会核对。
- 交付说明里提醒用户用 Word 打开终验图片显示（本机无 Word/LibreOffice 时只有结构校验）。

## 常见问题与处置

| 现象 | 处置 |
| --- | --- |
| `text-in-box` FAIL | 缩短文字（≤20 字）或把长机制名拆成「编号 + 短名」两行 |
| `edge-through-node` FAIL | 改 `layout`（column↔row）、调整分组顺序让边不跨组、或把跨组边改成经顶带/底带中转 |
| `label×label` FAIL | 两条边的标签在同一水平段：错开分组间距、或只给关键边加标签 |
| 图太长（长宽比 <0.9） | 分组 ≤4 时改 `row` 布局；分组 >4 时拆成总图 + 子图 |
| 文字缩进文档后太小 | 减少每行字数、减少分组数，不靠缩字号硬塞 |
| 术语与正文不一致 | 改 spec 跟正文，不改正文跟图；正文术语改了要重新派画图员 |
