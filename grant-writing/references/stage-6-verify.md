# 阶段 6：成稿验证、多轮校对、构建 docx

阶段 5 落盘申请书后、首次交付用户前，本阶段自动执行，不需用户确认。分三步：**6-甲 机械校验 + 九条验证点（审查员）→ 6-乙 多路校对（≥2 个校对员并行 + 写手修复）→ 6-丙 构建 docx（构建员）**。不通过就修复、修完重验，循环推进；迭代不超过 20 轮。
**落盘**：`06-质量自检.md`（阶段进度表、九条验证点、校对轮次、机械校验汇总、遗留事项）、`06-校对问题单_第K路.md`、`05-申请书.docx`。

## 6-甲 机械校验与九条验证点

**先机械后人工。** 主 agent 先跑 `scripts/check_md.py`（C01–C20：禁词、政策直引计数、ASCII 图、图表编号与先文后图、缩进、标题体例、字数双口径、引用首现顺序、口径一致、分类命名一致、研究内容时态、风险措辞、周期结构、目标结构、术语变体、图片分辩率、段落长度、摘要位置）。机械校验有错误不进人工审查。

**审查员**（1 个子 agent，不是写手）对照下面九条逐条评审，每条给出「通过 / 不通过 + 证据位置（行号 + 原文片段）」，不许目测打勾：

1. **背景有数字**：研究背景与问题描述部分至少出现 2 个已核验的实际数字，每个数字都能回指 `背景数字核验.md`。
2. **重要性靠论述**：全文不出现自评断言（C01）；政策直接引用 ≤2 处（C02）。
3. **现状分类有逻辑**：有显式分类句；分类名词与维度匹配、五处一致（C12 零警告 + 人工核对五处）；**每类先写总体原理再写代表工作**（总体原理自检：删掉代表工作句子后仍是完整论述）；每类不足从该类原理推导（「该原理决定了……」）。
4. **方法原理可达**：研究目标与方法论述说明原理机制，从原理上论证本项目方法能解决研究问题，并点明已有方法因哪条原理限制做不到。
5. **难点 2–3 条且被克服**：收束段收拢 2 或 3 条难点，每条论证为什么难；后文每项研究内容的方法都能回指克服了哪条难点。
6. **创新对照传统不足**：每个创新点写成「传统方法原理 → 固有不足 → 本方法原理 → 为何能消除该不足」。
7. **框架图 ≥1**：全文至少 1 张总体研究框架图 + 每项研究内容 1 张架构图，均为 PNG（C03 零错误），图内模块与正文研究内容一一对应，每图有 `.audit.txt` 且审计全 PASS、视觉自检两轮通过。
8. **图表有编号、先文后图**（C04–C06 零错误）。
9. **段首缩进**（C07 零错误）。
10. **目标与周期与风险的结构**：总目标含「分为 A、B、C、D」与关系句（C16 零警告 + 人工核对 A–D 与分目标逐字一致）；研究周期首段含研发思路与分阶段依据（C15 零警告）；风险每条有控制 + 兜底 + 不影响总体目标，末句「可控」（C14 零警告 + 人工核对控制手段在研究内容里存在）。

审查员把结果写入 `06-质量自检.md` 的「九条验证点」表（第 10 条并入表内，标「10」）。

## 6-乙 多路校对（解决「文字描述问题」）

机械校验与九条验证点管的是结构与论证，管不了句子层面的毛病：搭配不当、指代不清、术语漂移、长句失控、并列不当、连接词误用、数字格式不统一。这些是评审读起来「不顺」的根源，必须由独立的校对员逐句过。**写手不校对自己的稿。**

**派法**：≥2 个校对员同一条消息里同时派，各自独立，只出问题单不改稿。两路 brief 侧重不同：

- **第 1 路（语言层）**：语法与搭配、成分残缺、指代、标点、数字与单位格式、中英混排空格、错别字、重复啰嗦。
- **第 2 路（逻辑与一致性层）**：段落首句是否点题、句间连接词是否成立、术语是否唯一、口径是否一致（篇/套/份/指标数值）、研究内容与目标/难点/创新点是否对得上、时态、分类名词五处一致、图内术语与正文一致、有无自评断言与政策腔。

**校对问题单格式**（`06-校对问题单_第K路.md`）：

```
| # | 位置(L行/章节) | 原文(≤40字) | 问题类型 | 问题说明 | 修改建议 | 严重度(高/中/低) |
```

**问题类型清单**（校对员逐类扫，每类至少扫一遍全文）：

1. 成分残缺或多余（缺主语/宾语；「进行」「加以」「开展」冗余）
2. 搭配不当（「提升…质量」「解决…水平」「建立…机制」动宾不搭）
3. 指代不清（「其」「该」「上述」无唯一先行词）
4. 术语不一致（同一概念多种叫法；正文与图与摘要不同名）
5. 长句失控（单句 >80 字或 >3 个分句）
6. 并列不当（「A、B 和 C 等」层级不一；「和」「及」「以及」混用）
7. 连接词误用（然而/因此/从而/进而的逻辑与实际不符）
8. 数字与单位格式（阿拉伯/汉字数字混用；区间符号「–」与「至」混用；百分号空格）
9. 中英混排空格（「CUDA 兼容」与「CUDA兼容」混用）
10. 重复啰嗦（同一段内同一短语 ≥2 次；「具体而言」「归结起来」堆叠）
11. 时态错误（研究内容里「已实现/已完成」）
12. 口径不一致（同一数字两处不同）
13. 自评断言与政策腔（「非常重要」「意义重大」；政策引文 >2 处）
14. 段落首句不点题（首句是例子或背景而不是本段功能）
15. 分类名词漂移（「五类方法」与「五个层次」混用）
16. 风险后果裸负面词（失败/不收敛/失真/崩溃）
17. 总目标/分目标/研究内容/图 四处的名称不逐字一致

**修复与复验**：主 agent 合并两路问题单、去重、按严重度排序，交给写手一张返工单（只改这些，不顺手润色）；写手修完，主 agent 再派 1 个校对员（可用第 1 路续接）复核返工单上的每一条是否已修、是否引入新问题；直到高/中严重度清零，低严重度可留但要在 `06-质量自检.md` 列明。**至少两轮校对**（首轮 + 复核轮），首轮高/中问题 >30 条时加一轮。

**逐轮落盘**：`06-质量自检.md` 记每轮：轮次、校对员路别、发现数（按类型分布）、修复数、遗留数、脚本输出摘要。

## 6-丙 构建 docx（构建员）

```bash
PY=~/.claude/skills/grant-writing/.venv/bin/python
S=~/.claude/skills/grant-writing/scripts
$PY $S/build_docx.py   <grant目录>/05-申请书.md --out <grant目录>/05-申请书.docx [--template <grant目录>/template/模板.docx]
$PY $S/verify_docx.py  <grant目录>/05-申请书.docx <grant目录>/05-申请书.md [--allow-prefix N]
```

两个脚本退出码都为 0 才算 docx 交付完成；技术要点与坑见 `docx-build.md`。每轮修订后重跑。

## 迭代机制

- **修根因不修表象。** 每条不通过都要定位根因所在的阶段落盘文件：分类不达标回阶段 3 的基准案与调研论证重分；难点与方法对不上回研究内容重写；数字无出处回阶段 2 补核验；句子层问题回写手。不允许只在成稿上换个说法绕过验证点。
- **全量重验。** 每轮修复后机械校验、九条验证点、校对复核全部重跑一遍，不只验上一轮的失败项——修复极易引入新违规。
- **20 轮上限。** 到上限仍有未过项时停止迭代，如实向用户报告：已通过哪几条、剩余哪几条、卡住的原因。不降低验证标准假装修好，不带病静默交付。
- **首版交付物**：`05-申请书.md`、`05-申请书.docx`、`figs/`、`06-质量自检.md`、两路校对问题单、`check_md.json`；交付说明里提醒用户用 Word 打开终验图片显示。

## 交付前最终清单（审查员在九条验证点与校对之后过一遍，每条写「是」或「否 + 改了什么」）

1. 全文是否为研究性表述，删掉系统名之后段落仍然成立？
2. 现状的每条不足是否都有一条研究内容对应，且没有多出来的内容？每类现状是否先写了总体原理再写代表工作？困难或问题的引出是否先总说、后分说？
3. 每个创新点是否写到了原理层？关键科学问题是否只有一个，且每项内容的关键问题都是它的分解？
4. 摘要与正文的成果数量、术语、指标是否逐字一致？总目标的 A–D 与分目标、研究内容标题是否逐字一致？
5. 课题意义是否从行业需求起笔（已核验数字立需求，非政策开篇）？
6. 总目标是否写出「可分为 A、B、C、D」与四者关系？分目标能否还原出总目标？
7. 研究内容是否覆盖完整链条，包括验证与收尾？
8. 技术路线是否每个模块单独成段，每段用「在〈问题〉方面」展开、末句给出首先到最后的执行顺序？
9. 技术指标、研究成果、进度安排三者的原型套数、报告份数、论文篇数是否与口径表一致，每条指标都有可演示的验收口径？
10. 每张图是否标出了数据对象与支撑关系、审计全 PASS、视觉自检两轮通过、图与图的术语一致？
11. 研究内容与技术路线里的每个机制、数据对象和步骤，是否都能回指到 `05-已有工作提炼.md`？已有进展是否只写在研究基础里？
12. 字数、标题层级、段落体例是否符合格式说明？字数口径是否双报告？
13. 需求是否以行业事实起笔、政策只在收束处佐证？重要性论证的数字是否全部回到原文核对？
14. 现状的分类名词是否与分类维度匹配且五处一致？每篇代表工作的归类是否有精读记录依据？考核指标是否全部为正向条目？研究周期是否先思路后分阶段、阶段间有衔接句？
15. 术语是否通过可读性审查：无行话裸奔、同一概念全文用词唯一、正文/图/科学问题名称三者一致？团队段是否未复述模板硬性要求、隐私字段留空并已提醒？
16. docx 是否 build/verify 均退出 0、图片段落自动行距、图片不超版心？
17. 正文引用的每篇论文是否都有本地 PDF 全文与需求导向精读记录？`待补全文.md` 是否清空或豁免？有没有论断只凭摘要写出？
18. 入库论文是否超过 80 篇、CCF/权威期刊与近 5 年占比达标、每篇有阅读记录？迭代是否 ≤20 轮，仍有未过项时是否如实报告？
19. 是否先经三案竞标、五条标准选优并落盘？后续分类、难点、创新方向是否都从基准案传导？
20. 校对是否 ≥2 路独立、≥2 轮（首轮 + 复核），高/中严重度问题是否清零，低严重度遗留是否列明？
21. 风险节每条是否「风险 + 后果 + 控制 + 兜底 + 不影响总体目标」四段齐全、末句「可控」？控制手段是否都能在研究内容里找到？

## `06-质量自检.md` 结构

```
# 06 质量自检（vN-YYYYMMDD）
## 阶段进度表          ← 主 agent 维护：阶段 | 执行者 | 交接物 | 门禁 | 日期
## 机械校验汇总        ← check_md.py 退出码、错误/警告数、关键发现；verify_docx 摘要
## 九条验证点（第K轮） ← 审查员填：# | 验证点 | 结论 | 证据位置
## 校对轮次            ← 轮次 | 路别 | 发现 | 修复 | 遗留 | 问题单路径
## 口径核对            ← 篇/套/份/指标在摘要、目标、成果、周期各处的值
## 遗留事项            ← 如实报告：未过项、待用户确认项、低严重度未修项
```
