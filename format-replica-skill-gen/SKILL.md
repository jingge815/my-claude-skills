# 文档格式复刻 Skill 生成器

这是一个「生成 Skill 的元 Skill」。它接收用户给出的任意文档，只抽象其排版结构、写作范式、页面框架、层级规范与视觉风格，产出一份可独立执行的「格式复刻子 Skill」。用户日后把内容主题交给那个子 Skill，即可生成与原文档格式、风格、结构一致的新文档。

本技能的产出物是**子 Skill 指令集本身**，不是按原格式写成的新文档。用户只说"按这个格式写一篇关于 X 的文档"时，先完成本技能的解析与子 Skill 生成，再明确告诉用户：写正文是子 Skill 的事，需要的话可以接着用刚生成的子 Skill 来写。

## 何时使用本技能

用户提供（或指明路径）一份想要"照着格式来"的文档——幻灯片、Word、Markdown、纯文本大纲皆可——并希望得到一个以后能反复套用的格式规范，而不是这一次的改写结果。

以下情况不用本技能：

- 用户已经有一份格式规范，只是要把新内容填进去 → 直接按那份规范写，不必再生成一次 Skill。
- 用户要的是内容层面的改写、摘要、翻译 → 那是普通写作任务。
- 用户要的是需求文档、技术设计、代码评审 → 分别是 `requirement-doc`、`tech-design-doc`、`code-review-doc` 的职责。

## 不可违背的原则

1. **形式唯一。** 只抽取形式属性：层级、篇幅、布局、样式、模块功能、句式节奏、衔接方式。分析过程与最终子 Skill 中，不得出现原文档的专有表述、数据、案例、人物、机构、产品名、观点或结论。需要举例时，只用占位符（「【论点】」「【数据口径】」「【图示对象】」），不得用原文句子改写后冒充形式描述。
2. **读不到就不写。** 形式特征必须来自对文档的实际观察。某种页型、标题级别、图表、编号体例在原文中没有出现，就在子 Skill 里写明"原文未使用，不作为本格式的必备项"，禁止为了凑满模板而编造一套"看起来专业"的规范。
3. **颗粒度下沉到最小可复用单元。** PPT 至少到单页：每一种重复出现的页面模板单独成条，写清区域划分与模块顺序。Word / Markdown 至少到段落：每类章节写清段落数量区间、每段的功能定位、首句 / 中段 / 收尾各自承担什么。观察不到的层级如实标"未观察到"，不向上位层级脑补。
4. **统计先于形容词。** "标题较短""段落匀称""术语密度高"这类判断，必须附带计数：总页数或总章节数、标题字数区间、每页要点条数、段落数区间、大致句长。数量从文档数出来，不估计一个整数充数。
5. **子 Skill 必须能脱离原文档独立执行。** 生成结果里不得写"参照原文第 N 页""保持与上传文档一致"这类回指。执行者只拿得到这份子 Skill 和用户的新主题，因此每条规范都要自洽、可操作。
6. **新内容不回填。** 本技能结束于子 Skill 交付。即使用户在同一句话里给了新主题，也先交付子 Skill，再询问是否立即用它生成文档；不要在同一轮里既解析又写正文。
7. **版权与引用边界。** 子 Skill 描述的是通用结构与风格约束，不嵌入原文句子、不复述原文结构到可以还原出原文的程度（例如不按顺序逐页转写原文每页标题）。章节框架用功能名（「背景」「方法」「结果」）而不是原文标题原文。

## 标准工作流程

严格按阶段推进。解析未完成不得开始写子 Skill；文档读不全不得假装已经解析完。

### 阶段一：接收并确认范围

- 明确目标文档：用户上传的文件、给出的路径，或粘贴在对话中的正文。一次只解析一份主文档；用户给了多份时，先问以哪一份为骨架、其余是对照还是合并。
- 识别类型：PPT/PPTX、Word/docx、Markdown/md、纯文本。扩展名与实际内容不一致时以内容为准，并在子 Skill 的「格式总则」里注明源类型。
- 向用户确认三件事（文档本身已足够明确的可以不问）：产出的子 Skill 希望落盘到何处（默认当前工作目录，文件名 `format-skill-<文档类型>-<风格简称>.md`）；风格简称用什么（从形式特征提炼，如"学术答辩""周报"，不用原文标题）；是否需要同时覆盖演讲者备注 / 页眉页脚 / 参考文献等次要区域。
- 确认后用一句话复述任务边界："只抽取形式，不保留内容，产出子 Skill，不写新文档正文。"

### 阶段二：把文档变成可观察的结构

按类型选择读取方式。目标是拿到**结构与样式**，读取过程中避免把大段原文抄进后续推理。

**PPT / PPTX**

- `.pptx` 是压缩包。解到临时目录后读取 `ppt/presentation.xml`（幻灯片顺序）、`ppt/slides/slideN.xml`（每页形状与文本框层级）、`ppt/slideLayouts/`、`ppt/slideMasters/`（母版与版式）、`ppt/notesSlides/`（备注，若存在）、`ppt/theme/theme1.xml`（主题色与字体方案）。
- 每页记录：版式名、文本框数量与相对位置（左/右/上/下/居中，由坐标判断，不抄文本）、标题层级、正文是段落还是项目符号、要点条数、是否有图/表/图表占位、备注有无及长短量级。
- 文本只用于判断**功能角色**（这一框是标题、副标题、要点、图注、页码），判断完即丢弃字面内容。功能角色不确定时标"角色不明"，不要靠内容猜。

**Word / docx**

- 解压后读 `word/styles.xml`（样式名、大纲级别、字体字号、缩进、编号定义）和 `word/document.xml`（样式引用顺序、标题级别、段落、列表、表格、图片、题注）。
- 按样式统计：每种标题级别出现次数、各级标题之间通常夹多少段落、列表出现在什么功能位置（标题下、步骤说明、并列要点）、表格/图片/题注的相对位置与编号体例。
- 段落统计用区间（如"每节 3–5 段"）而不是逐段复述。句子级规范只抽象句长区间、有无主谓完整句、是否惯用被动、段首是否承担"本段主张"，不摘抄句子。

**Markdown / 纯文本**

- 直接读文件。统计标题层级与编号体例、各级标题下的段落数与列表用法、代码块/表格/引用块/图片出现的位置与密度、分隔线与强调（加粗、行内代码）的使用场景。
- 纯文本没有显式样式时，从空行、缩进、编号、全大写、下划线分隔等版式信号推断层级，并在子 Skill 里写明这些信号，避免把偶然换行当成规范。

文档损坏、加密、只给了截图或扫描件时：能从可见版式判断的部分照常抽取，其余在子 Skill 开头用「观察限度」列出，不编造未看见的样式。

### 阶段三：形式抽象

只在工作记忆里整理，不向用户展示原文摘录。覆盖下面与该文档类型对应的维度；某维度在原文中不存在，就显式记为"无"。

**PPT / PPTX 必覆盖**

1. 大纲结构：章节如何划分（按分隔页、按标题前缀、按母版切换）、层级深度、总页数、各功能段的页数占比、页面递进顺序（例如"总览 → 分点 → 收束"，用功能描述，不用原章节名）。
2. 单页框架：归纳出实际重复出现的页面模板（通常 3–7 种）。每种模板写清区域划分、元素排布（左文右图、上下分栏、居中、全幅要点等）、标题与正文字号层级、列表层级、强调手段（加粗、色块、编号）。
3. 功能页范式：封面、目录、章节分隔、内容页、数据/图表页、对比页、总结页、致谢页等——只列原文真正出现过的。每种写清模块顺序（标题、主张、论据列表、图注、备注）和各模块的篇幅量级。

**Word / docx / Markdown 必覆盖**

1. 目录层级：标题级数、编号方式（无编号 / 十进制 / 中文序号 / 章节号）、命名形态（名词短语还是完整句子，字数区间）、章节数量与篇幅占比。
2. 段落规范：每级章节的段落数区间、每段大致字数或句数区间、段落功能序列（引入、主张、展开、例证、过渡、收束——按原文真实顺序，不套固定五段）。段内写清首句功能、中段展开方式（定义、对比、因果、枚举）、收尾句功能。
3. 图表与要素：图、表、代码块、公式的插入位置（段前/段后/独立成节）、题注格式与编号规则、有序与无序列表各自的使用场景和缩进层级、引用、脚注、参考文献的排版。原文没有的项写"不使用"。
4. 语言风格：正式度、主动/被动比例的倾向、术语密度（高/中/低，并说明判断依据是术语重复出现的位置而不是术语本身）、句长偏好、段与段的衔接手段（显式连接词、标题切换、首句回指上一节功能）。只描述倾向，不引用原句。

### 阶段四：生成子 Skill

按下方「子 Skill 固定结构」写出完整 Markdown。写作时遵守：

- 每一条都是给未来执行者的指令，用祈使句，不用"原文这里……"的分析口吻。分析过程不进入子 Skill。
- 目录框架用功能槽位，不抄原标题。例如「1. 问题界定」「1.1 范围与非目标」，而不是原文章节标题。
- 篇幅用区间并允许用户主题本身更短时按比例缩小，写明缩放规则，避免子 Skill 强迫注水。
- 样式写到可执行的程度：字号层级、列表符号、编号格式、对齐、图表题注模板。无法从文件确定的样式（如主题字体在 XML 中是主题引用而不是具体字体名）写"沿用主题默认字体，层级关系如下"，不臆造字体名。
- 在子 Skill 末尾的使用说明里重申：执行时不得回看原文档，不得把本 Skill 里的占位符当成内容。

### 阶段五：交付

- 将子 Skill 写入约定路径，并把全文展示给用户（用户需要复制使用）。
- 用不超过五句说明：源文档类型、观察到的页面/章节模板数量、总篇幅量级、刻意没有写成规范的缺项、文件落点。
- 明确告知：子 Skill 已生成，可直接复制使用；它只约束格式。若要针对某个新主题生成文档，把主题交给这份子 Skill 即可。
- 不在交付说明里复述任何原文内容，也不评价原文观点。

## 子 Skill 固定结构

生成物必须且只包含以下五节，顺序不变。观察不到的子项写"本格式不使用"，不删节号，以免执行者以为是遗漏。

```markdown
# 格式复刻Skill：[文档类型]风格写作助手

## 一、格式总则
- 风格定位：【正式度、叙述姿态、适用场合，各用一句，不含原文档主题】
- 适用场景：【这种结构适合承载什么样的内容，用功能描述】
- 整体篇幅：【页数或字数区间、章节/页面数量区间、缩放规则】
- 观察限度：【源文件中未能确定的样式；没有则写"无"】

## 二、层级目录规范
- 标题层级：【级数、编号体例、命名形态、字数区间】
- 层级逻辑：【章节如何递进，用功能描述】
- 标准目录框架：
  1. 【功能槽位】
     1.1 【功能槽位】
  （只列原文中稳定出现的层级，不凑满三级）

## 三、章节写作范式
（PPT 以"页面模板"代替"章节"，一种模板一小节；文档以一级功能章节为一小节）

### 【功能名】
1. 核心功能：【这一单元对读者完成什么】
2. 篇幅：【段落数或要点条数区间、字数或句数区间】
3. 写作逻辑：
   - 开篇：【首段或标题下第一块写什么功能】
   - 展开：【中间用什么论证或展示方式，顺序如何】
   - 收束：【最后一块的功能，没有则写"不单独收束"】
4. 图表：【类型、位置、没有则写"不使用"】

## 四、排版与样式规范
1. 字体字号层级：【标题、正文、注释、页码的相对层级；不确定的字体不臆造】
2. 列表、引用、注释：【符号、缩进、使用场景；不用的写明】
3. 图表标题与编号：【格式模板，如"图 1-1  【图示对象】"】
4. 页面布局：【分栏、对齐、页边距或幻灯片区域划分、页眉页脚】

## 五、使用说明
- 输入：用户给出内容主题、受众、以及必须包含的要点。
- 生成：严格按第二至第四节铺排；内容不足时按总则的缩放规则缩减，不编造事实填充篇幅。
- 禁止：不回看、不引用、不模仿源文档的具体内容；占位符必须替换为用户主题下的真实内容，不得原样输出。
```

## 实操要点

- **先画结构再读句子。** 样式 XML、母版、标题样式能回答的问题，不要靠通读正文回答。正文只用来判断模块功能和句式节奏，判断完就停。
- **模板按重复度合并。** 只出现一次、且与某模板仅差一个装饰元素的页面，归入该模板并注明变体，不为每一页各写一节。
- **数量写区间。** 文档里某级标题下段落数是 2、4、5、3 时，规范写"2–5 段"，不写"通常 4 段"把波动抹平，也不写死成唯一值。
- **中英文混排只描述现象。** 若标题用英文、正文用中文，把这写成规范；不要因此把某个英文术语带进子 Skill。
- **不评价好坏。** 不说"这个结构更专业""建议优化成……"。用户要的是复刻，不是改版。发现明显不一致（如同级标题编号体例不统一）时，在「观察限度」里说明以出现次数更多的体例为准。
