# 图表生成规范

模板正文页的图表槽（`矩形 2`）只是一块 accent1 色块加「图/表」三字，
**不是成品图**。交付的 PPT 必须把这块换成真正的图。风格、配色、几何
全部跟 `assets/template.pptx` 走。

**图表只有一个模块：`scripts/shapes.py`。**

- 自己画的图 → `render_shapes()` 生成 **PPT 原生形状**（圆角矩形、文本框、箭头、
  饼图扇区），在 PowerPoint 里能点选、改字、挪框、换色。
- 申请书原图（`type: image`）→ `render_image()` 按槽位等比缩放居中，写成 PNG。
  原图本来就是一张现成的图，不重画也不改它的内部结构。
- 外部工具画好的位图 / SVG → `external_image()` 按槽位等比摆放，同样按 `image` 嵌入。
- `to_preview_png()` 把画布按同一套几何画成 PNG，供生成后自查版式
  （有没有压字、出框）；PowerPoint 里的实际效果以形状为准。
- `shape_overlaps()` / `out_of_canvas()` / `blank_ratio()` 是图内自检：
  框压框、出框、图缩在一角，生成时就报出来，不等交付后才发现。

位图渲染（早先的 `draw_figure.py`）已经删掉：它和 `shapes.py` 各实现了一遍同样的
九种图，两边的数量上限、字号、间距迟早会分叉——事实上已经分叉过。
一套图只留一份实现。

**原生形状优先，但不是唯一选择。** 原生形状能在 PowerPoint 里改字挪框，
所以默认用它。但图复杂到原生形状画不出来时（多路分支的流程、带回环的状态机、
节点超过密度上限的架构图），**可以用外部工具画成 PNG 或 SVG 再嵌进来**——
一张看得清、结构对的位图，胜过一张硬塞进 `framework` 的残图。
用外部图的三条约束：

1. 图内文字按最终呈现尺寸折算不低于 14 磅，和自己画的图一个标准；
2. 配色仍只用模板主题色，白底、细描边；
3. 在生成说明里写明这张是外部工具出的，用了什么工具、为什么不用原生形状。

PowerPoint 的 SmartArt 也可以用——它本身就是原生形状，能编辑。但本技能的脚本
不生成 SmartArt，要用就在生成后手工替换，并在生成说明里注明。

一句话概括这份规范：**图要美观、简洁，而且一眼看得出结构。**

## 一、硬规则

1. **美观、简洁，但不简陋。** 一页 1–3 组图，每组只讲一件事，层次清楚、框对齐、留白均匀，
   同一页里的节点大小一致，颜色只用模板主题色。不要为了填满槽位而堆节点，
   也不要把三五个框随便一摆就交卷——图里必须能看出关系：谁包含谁（分层框架）、
   谁先谁后（流程）、谁导致谁（逻辑链）。看不出关系的图，等于把文字换了个排法。
2. **风格跟模板，不另起炉灶。** 配色只用主题色：accent1 `#5B9BD5`、accent2
   `#ED7D31`、accent5 `#4472C4`、accent6 `#70AD47`、accent4 `#FFC000`、
   accent3 `#A5A5A5`、dk2 `#44546A`。白底、细描边、无阴影堆砌、无装饰插画。
3. **用原图还是自己画：先收素材，再逐槽选，不许默认一律自己画。**
   选之前必须先跑 `collect_assets.py` 把素材里的图和表全收出来、逐张看过并分类
   （门禁 A 第 1–2 条，见 `review-spec.md`）。然后每个矩形按下表选一次，
   选择理由写进图表规划的 `decision`：

   | 情况 | 怎么办 |
   |---|---|
   | 素材里有能对上的图，铺到该槽 ≥ 110 DPI | **直接用**：`{"type": "image", "path": ...}`，放大到铺满这个矩形，只裁四周空白、图注、水印与无关内容，生成说明里注明来自哪一张 |
   | 素材里有，但铺到该槽 < 110 DPI | **按它的结构重画**：分层还是分层、流程还是流程，用 `flow` / `framework` / `logic` / `compare` |
   | 素材只是表格截图 | **按原有行列重画成 `table`**，不嵌截图、不改列 |
   | 素材里没有 | **自己画**，而且要仔细画 |
   | 结构复杂到原生形状画不出 | **外部工具出 PNG/SVG**，按 `image` 嵌入，受同样的字号下限约束 |
   | 确实做不出来 | 才允许留「待补充」，并写明缺的是素材、标识还是尺寸 |

   **素材看着小 ≠ 像素不够。** 素材在原 PPT 里被放小是常事：先看文件本身的像素，
   不看它原来的显示尺寸。`清单.md` 直接给了「铺到 17 cm 的 DPI」这一列，
   `shapes.image_effective_dpi()` 可按任意槽位尺寸算。像素够就放大铺满，
   不要因为原图放得小就把内容裁掉。

   自己画的时候：先读透该节，把结构、步骤、层次都理出来再动手——节点该有几个就画几个，
   每步该有子动作就挂 `children`，不要交一张只有三个空框的简图。画完自己看一眼：
   能不能看出这个项目在做什么、分几步、谁驱动谁；看不出来就回去补。
4. **不编数据。** 柱状图、饼图、对比表里的数字必须来自申请书。没有量化数据
   时改画结构图（流程 / 框架 / 卡片 / 对比栏），不要用假数字凑一张柱状图。
5. **必须是图，不是文字表格。** 槽位 17.06 × 9.03 cm。自己重画的图默认是流程、
   逻辑链、分层框架或左右对比，节点之间要有箭头或层级关系。**禁止**用
   `table` / `cards` 把申请书段落改写成格子里的句子交差——那看起来是图，
   读起来是文字罗列，而且格子一多字就看不清。`table` 只留给「主要技术指标」
   这种本来就是指标对照表的页；`cards` 只留给第 2 页的四个栏目和第 11 页的成果分类。
   密度上限（`shapes.py` 已按此写死，超出的项会被截掉）：流程 ≤5 步（每步 ≤3 个子步骤）、
   逻辑链 ≤4 环、框架 ≤4 层（每层 ≤4 项）、卡片 ≤4 张（每卡 ≤3 行）、
   对比每侧 ≤4 条、饼图 ≤5 块、表格 ≤5 行、柱状 ≤6 条、甘特 ≤6 条。塞不下就删次要项，
   **不许再把字号降到看不清**。
6. **任何"标签带 + 内容框"的结构，标签必须有独立行高。** 层名、时间轴刻度、表头
   这类文字，要先按字号算出它自己占多高（`shapes.py` 里用 `_title` / `axis_h` /
   `name_h` 这类量），内容框从它下面再开始，不能共用同一段 y 区间。
   内容框一律**不填色**（透明，只留描边）——这样即使挨得近，也不会出现"白框盖住
   层名"这种事故。分层框架的层名被遮、甘特图的「1–6 月」被柱子压住，都是这个原因。
7. **图内文字按框定字号，上限 18 磅、下限 14 磅。** 每段文字取它那个框能放下的最大字号，
   不按槽高一刀切：宽槽里一句短话用 18 磅，窄槽里放不下就降，降到 14 磅仍超框就缩短文字。
   不许出现文字画出文本框。节点标签能用原词就用原词，只在降到 14 磅仍放不下时才缩短。
8. **带箭头的图，箭头必须看得见。** 相邻两个节点之间留出不小于 0.7 cm 的空隙，
   节点不超过 3 个时留到 1.3 cm。箭头从空隙的一侧画到另一侧，两头不贴节点边框。
   空隙小到箭头只剩一条线时，加大空隙，不缩小箭头。
9. **图文同页对应，且不许重叠。** 图里出现的标签、数字、阶段名，必须能在右侧
   要点或申请书原文里找到出处。图只占图表槽，正文只占文字槽；不要把申请书原图
   （往往带自己的图注、坐标轴小字）直接铺满槽位后，再在旁边堆一段会压到图上的文字。
10. **画图之前先把那一节读完。** 这是本技能最容易出错的地方：需求分析、研究现状
   这类页，把要点抄进格子不算图。要读完该节，找出**因果关系**——痛点是什么、
   为什么会成为缺口、本课题怎么回应——再用 `logic` 画成带箭头的逻辑链。
   同理，技术路线要读「研究思路方法与技术路线」那几段，抽出实现步骤和每步的动作，
   用 `flow` 画成分层流程；研究内容要读出「具体研究内容」里的部件划分，用
   `framework` 画成分层结构。
11. **只取本页对应章节的事实。** 研究内容的每一页不得搬其他章节的架构
    （典型错误：研究内容页出现申请书里另一处的「平台架构框图」）。

## 二、按页选图（默认）

| 页 | 图 | 画什么 |
|---|---|---|
| 第 2 页 积累 | 按模板四个槽各一张，顺序固定 | 槽 1（宽而矮）放合作厂商，优先用网上找到的 logo 拼图，找不到才用卡片；槽 2（小方块）放一项量化效果；槽 3 放论文或证明；槽 4（窄而高）放技术演进，不超过 3 层。每张图按该槽的尺寸画，不跨槽 |
| 第 3 页 需求 | `logic`，可加第 2 组 | 因果链与右侧标题同一条逻辑：重要性 → 瓶颈 → 解决途径 → 所需软件栈。第 2 组放架构对照或关键数据图 |
| 第 4 页 现状 | `framework`，可加一张 `table` | 框架图画模块之间的关系（谁给谁输入）。有可核对的差异维度时用表，表不能替代总述文字 |
| 第 5 页 概述 | `framework` 一张 | 块名与右侧研究内容、子研究点用词一致。不画步骤，不提前画后面几页的方法细节 |
| 研究内容第 1 页 | `framework` | 分区名与右侧一级标题同名，突出这项内容的几个子问题 |
| 研究内容第 2–3 页 | `flow`（带 `children`） | 3–5 步，每步 2–3 个子步骤，步骤名能在右侧文字里找到。没有独立的第二张过程图就不要第 3 页 |
| 主要技术指标 | `table` | `bar` | 指标名 × 预期值（有对比列就加一列）。这是唯一默认用表的页 |
| 成果及考核 | `cards` | `flow` | 论文 / 专利 / 软著 / 系统 各一张卡，每卡一行数量 |
| 周期与进度 | `gantt` | `flow` | 阶段 × 时间轴；阶段名写短 |
| 经费预算 | `pie` | `bar` | 科目占比；科目 ≥6 个时改用水平条 |

封面、结束语不配图。申请书里有更贴切的原图时，把该页 `type` 改成 `image`。

## 三、JSON 契约（写入每页的 `figure`）

`figure` 是一个对象，或最多 3 个对象的数组，不要写成一句配图说明。

画每一页之前先列一张小表：矩形名、宽高、放什么图。`figure` 数组按这些矩形的顺序给，每张图按对应矩形的宽高画，而且每张图单独画、单独检查图内没有重叠。只画一张图时，它要铺满该页全部矩形合起来的区域。不切分矩形、不把一张图铺进另一个矩形、图与图不重叠、图与正文不重叠。画完要检查两组图的外接框不相交、也不超出页面（19.05 cm 高）。半槽高度不够时，图内字号从 18 磅降到 14–16 磅，层名和步骤名同步缩小，不允许字超出色块。 半槽只有约 4.4 cm 高，最多放 3 层或 3 行，不要在半槽里画 4 层框架或 4 步流程；层数多的图放整槽，第二组图改用对比栏、表格或卡片这种矮图。
`scripts/build_ppt.py` 把图表槽按组数切开，每组调用 `shapes.py` 生成原生形状
（`type: image` 才走位图）。超过 3 组会在校验里报告，多出的不画。

```json
"figure": [
  { "type": "framework", "title": "技术演进", "layers": [] },
  { "type": "logos", "title": "合作厂商", "items": [{"path": "厂商A.svg", "label": "厂商A"}] }
]
```

### `logos` — 一组标识或证明材料

`items` 每项是路径字符串，或 `{"path": "...", "label": "..."}`。放得下就一行，放不下两行，最多 4 列。路径打不开的项跳过并在校验里报告，不留空框。

**标识一律等比，不许拉变形。** 脚本按原图像素比算出它在格子里的实际宽高再居中，
不把图拉满格子——商标被拉扁比图小一点严重得多。所以给 `logos` 的素材
最好是透明底、裁掉四周空白的原始标识。

厂商名单从申请书和用户给的团队资料里来，**skill 不预设任何厂家**。
取标识按顺序试：

1. 素材里标了「厂商标识」类的图（`collect_assets.py` 收出来、人工分过类的）；
2. 素材里没有，逐家上网搜官方标识（SVG 或透明底 PNG）；
3. 搜不到的那一家退回文字卡片，并在生成说明里写明是哪家、试过什么关键词。

不许不搜就直接上文字卡片。列数受槽位限制时（第 2 页槽 1 按 4 列排），
放不下的厂商在正文和旁白里用「等信创企业」概括，不要硬塞第 5 列。

公共字段：`type`（必填）、`title`（选填，画在图内顶栏）。

### `image` — 复用申请书原图

申请书该节有能对上的图时，**这是首选**：把它复制进 PPT，而不是另画一张。
`extract_doc.py` 会把内嵌图片抽到 `申请书_media/`，直接指过去即可。
`caption` 写原图的图题（有就写，没有可省）。

```json
{ "type": "image", "path": "申请书_media/image3.png", "caption": "图1 总体技术框架" }
```

嵌入前**酌情处理**：图注、边框、水印、大片留白先裁掉；只截核心区域也可以
（用 `PIL` 或任意图像工具裁好再指过去）。原图字在 17 cm 槽位里太小、
或它本身就是一张表格截图时，改成按它的结构重画，不要硬嵌。

### `table`

```json
{
  "type": "table",
  "title": "主要技术指标",
  "columns": ["指标", "预期", "对照"],
  "rows": [["编译时长降幅", "≥30%", "现有工具链"], ["通过率", "≥95%", "基准测试集"]]
}
```

### `bar` — 水平条（适合科目名较长）

```json
{
  "type": "bar",
  "title": "经费构成",
  "unit": "万元",
  "items": [
    { "label": "设备费", "value": 40 },
    { "label": "材料费", "value": 25 }
  ]
}
```

分组对比用 `values` + `series`：

```json
{
  "type": "bar",
  "title": "指标对照",
  "series": ["现有", "本课题"],
  "items": [{ "label": "吞吐", "values": [1.0, 1.4] }]
}
```

### `pie`

```json
{
  "type": "pie",
  "title": "经费预算",
  "unit": "万元",
  "items": [
    { "label": "设备费", "value": 40 },
    { "label": "劳务费", "value": 30 },
    { "label": "其他", "value": 10 }
  ]
}
```

### `gantt`

`start` / `end` 是时间轴的下标（从 0 起，半开区间：`end` 不包含）。

```json
{
  "type": "gantt",
  "title": "进度安排",
  "axis": ["2026Q1", "Q2", "Q3", "Q4", "2027Q1", "Q2"],
  "items": [
    { "name": "需求分析与方案", "start": 0, "end": 2 },
    { "name": "核心算法实现", "start": 1, "end": 4 }
  ]
}
```

### `flow`

研究内容的过程页用带 `children` 的分层流程。`children` 里每一项是该步的子动作，
脚本会画成阶段框 + 框内子步骤 + 阶段间箭头。没有 `children` 时退回一排步骤框，
只适合 3–4 个很短的步骤，不适合技术路线。

```json
{
  "type": "flow",
  "title": "技术路线一：编译到执行",
  "steps": [
    { "label": "前端", "children": ["源语言解析", "IR 构建"] },
    { "label": "优化", "children": ["数据流分析", "目标无关优化"] },
    { "label": "后端", "children": ["指令选择", "寄存器分配"] },
    { "label": "执行验证", "children": ["基准测试", "结果对照"] }
  ]
}
```

### `framework`

```json
{
  "type": "framework",
  "title": "总体方案",
  "layers": [
    { "name": "问题层", "items": ["语义鸿沟", "优化空间"] },
    { "name": "方法层", "items": ["表示", "分析", "生成"] },
    { "name": "验证层", "items": ["基准", "案例"] }
  ]
}
```

### `logic` — 逻辑链（需求分析、研究现状）

节点之间是因果关系，箭头本身就说明「为什么」。写之前先把该节读完，
每个节点一句短话，不要整段抄。

```json
{
  "type": "logic",
  "title": "需求分析：存储墙到编译缺口",
  "nodes": [
    { "label": "痛点", "desc": "计算与存储分离，访存主导推理时延与能耗" },
    { "label": "现状", "desc": "编译与编排均面向 GPU 统一地址空间" },
    { "label": "缺口", "desc": "多单元独立编址、跨单元须经主机，无人适配" }
  ],
  "foot": "本课题：面向存算一体架构的 AI 编译软件栈"
}
```

`nodes` 2–4 个，`foot` 是底部那条结论带（可省）。节点标签 ≤6 字，`desc` 一到两句。

### `compare`

```json
{
  "type": "compare",
  "title": "研究现状",
  "left": { "title": "现有方法", "points": ["依赖手工规则", "跨架构泛化弱"] },
  "right": { "title": "本课题", "points": ["可学习表示", "多后端统一 IR"] }
}
```

### `cards`

```json
{
  "type": "cards",
  "title": "编译领域积累",
  "items": [
    { "title": "论文", "lines": ["CCF-A 会议 3 篇", "SCI 一区 2 篇"] },
    { "title": "项目", "lines": ["国家重点研发 课题骨干", "自然科学基金面上"] }
  ]
}
```

## 四、画不出时的退路

1. 自己画的图走 `shapes.render_shapes()`，**不需要 Pillow**。只有两种情况下才依赖它：
   `render_image()` 嵌申请书原图，以及 `to_preview_png()` 出自查预览图。
   缺 Pillow 时原图那条路会失败并退回文字说明，先 `pip install pillow`。
2. `type` 不认识或数据字段缺失：该页退回文字说明，并在生成说明里写原因。
3. 申请书原图格式古怪（wmf/emf）：抽得出就尝试；打不开就按本页默认 type 重画。

## 五、自检

- [ ] 除封面、结束语外，每一页图表槽都是图，没有「图/表」三字
- [ ] 申请书该节有可用原图的页，已把原图复制进来并酌情裁切，来源写进生成说明
- [ ] 自己画的图是 PPT 原生形状（脚本报告里显示"形状图 N 个（可编辑）"），
      在 PowerPoint 里点得开、改得动
- [ ] 自己重画的图是流程 / 逻辑链 / 分层框架 / 左右对比，不是把句子填进格子
- [ ] 自己画的图够丰富：结构、步骤、层次都在，不是一张三个空框的简图
- [ ] 图美观简洁——框对齐、留白均匀、颜色只用主题色，一眼看得出关系
- [ ] 层名 / 轴标签 / 表头都有独立行高，内容框不填色，没有被白框或柱子压住
- [ ] 用 `shapes.to_preview_png()` 出过预览图，肉眼看没有压字、出框
- [ ] `shape_overlaps()` / `out_of_canvas()` 都是空：图内没有框压框、没有出框
- [ ] `blank_ratio()` 不超过 0.45（饼图、柱状、甘特、标识这类天然稀疏的放宽到 0.70）：
      图撑满了这个槽，不是缩在一角
- [ ] 用素材图的槽，铺到该槽尺寸后 ≥ 110 DPI（`image_effective_dpi()` 可算）
- [ ] 标识是等比的，没有被拉扁拉长
- [ ] 图标题没有和页面标题重复（重复了就删掉图标题，把高度让给图）
- [ ] 需求分析、研究现状两页画的是带箭头的逻辑链，读得出「痛点→缺口→回应」
- [ ] 研究内容过程页的图带步骤、子步骤和箭头（有 `children`），不是三个空框；右侧同时有要点
- [ ] 配色只有模板主题色，没有额外的红绿撞色或渐变
- [ ] 饼图/柱状图/表格里的数字能在申请书里找到
- [ ] 图内每段文字都在自己的框内，字号在 14–18 磅之间；窄槽里字号降过，没有按 18 磅画出框
- [ ] 带箭头的图，相邻节点空隙不小于 0.7 cm，箭头两头不贴框
- [ ] 图没有压到正文，正文框与图表槽上下沿对齐
- [ ] 用了申请书原图的页，在生成说明里注明来源；弃用原图（字太小、是表格截图、
