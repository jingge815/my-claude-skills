# 答辩旁白撰写规范

旁白要服务一个硬指标：**10 分钟讲完，总字数 1800–2000 字**（按每分钟约 200 字的正常答辩语速）。
写之前先定字数，写完必须逐页统计、核对总量。

## 一、逐页字数基准

以标准 14 页方案（研究内容 2 项）为例：

| 页码 | 页面 | 基准字数 | 说明 |
|---|---|---|---|
| 1 | 封面 | 70 | 自我介绍 + 题目，一句话进正题 |
| 2 | 编译领域积累 | 240 | **重点页**，技术积累是核心考核项，要给足；四个栏目（论文 / 项目 / 厂商 / 优化）都要带到 |
| 3 | 需求分析 | 150 | |
| 4 | 研究现状 | 150 | |
| 5 | 研究概述 | 210 | **重点页**，讲清总体思路与创新点 |
| 6 | 研究内容一 | 140 | |
| 7 | 研究技术路线一 | 130 | |
| 8 | 研究内容二 | 140 | |
| 9 | 研究技术路线二 | 130 | |
| 10 | 主要技术指标 | 130 | 指标要念准，数字不能含糊 |
| 11 | 研究成果及考核方式 | 120 | |
| 12 | 研究周期与进度安排 | 120 | |
| 13 | 经费预算 | 90 | |
| 14 | 结束语 | 70 | |

基准合计 1890 字，落在区间中段。研究内容多于或少于 2 项时，页数随之增减，按下列优先级调整：

1. **总量必须落在 1800–2000 字**，这是第一约束。
2. 重点页（第 2 页、第 5 页）不得低于 200 字，这是评审最关心的两页。
3. 封面与结束语各不超过 90 字，寒暄不占时间。
4. 需要腾字数时，从经费、成果考核、周期进度这类信息型页面里压，压缩比例不超过三分之一。

## 二、写法要求

- **说人话，不念 PPT。** 幻灯片上已经写了要点，旁白要补充"为什么"和"所以呢"，而不是把
  要点逐字念一遍。要点写"提出静态蓝图驱动的编排方法"，旁白就说清**为什么非得这么做**——
  "因为单元之间不能互访，运行期再决定数据放哪儿就来不及了，所以把放置全部前移到编译期"。
  旁白可以换说法、可以解释动机，但**不许引入幻灯片和申请书里都没有的数字**。
- **页间要接得上。** 每页开头用一句话承上，例如"讲完需求，再看现有研究做到哪一步了"。
  禁止每页都用"下面介绍……"这种同构开场。
- **术语第一次出现要落地。** 缩写、专有名词首次出现时给一句解释，之后直接用缩写。
- **数字读法要能开口念。** 百分比、金额、时间写成便于朗读的形式（"百分之十五"或"15%"均可，
  但同一份旁白保持一致）；关键指标念完整，不省略单位。
- **口径与申请书一致。** 旁白里的每个数字、每条结论都必须来自申请书原文，禁止四舍五入到
  走样、禁止把"预期"说成"已实现"、禁止添加申请书中没有的对比数据。
- **自称统一。** 全程用"我们"或"本课题"，不要一会儿"本项目"一会儿"我团队"。
- **收尾要稳，并且落到单位优势上。** 结束语旁白要呼应幻灯片上那句单位优势判断
  （编译方向的长期积累、质量保证与国产化保障能力、原型系统研制能力），最后用
  "请各位专家批评指正"这类常规表述收住，不写煽情句。

## 三、每页旁白的结构

正文页旁白按三段走，一段一句到两句：

1. **承上/点题**：这一页要回答什么问题。
2. **展开**：支撑该页要点的事实、方法或数据，只说要点里最重要的 1–2 条。
3. **落点**：一句话收在该页底部总结句的意思上（可以换说法，不要照抄总结句）。

封面页只有"问好 + 题目 + 一句总纲"；结束语页只有"一句总括 + 致谢"。

## 四、交付前自检

逐条核对，缺一不可：

- [ ] 逐页统计字数，总和落在 1800–2000 字。
- [ ] 重点页（第 2、5 页）各不少于 200 字。
- [ ] 封面、结束语各不超过 90 字。
- [ ] 每页旁白都标注了本页字数，末尾给出总字数与折算时长。
- [ ] 通读一遍：有没有书面语残留（"旨在""予以""进一步地"）、有没有同构开场、页与页之间
      是否接得上。
- [ ] 旁白里的数字与申请书原文逐个核对过。
- [ ] 按 200 字/分钟折算，总时长在 9–10 分钟之间。

`build_ppt.py` 会在生成时打印每页旁白字数、总字数与折算时长，直接拿它核对前四条；
后三条需要通读，脚本查不了。
