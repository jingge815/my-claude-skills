# 答辩旁白撰写规范

旁白要服务一个硬指标：**10 分钟讲完，总字数 1800–2000 字**（按每分钟约 200 字的正常答辩语速）。
写之前先定字数，写完必须逐页统计、核对总量。

## 一、逐页字数基准

以标准 14 页方案（研究内容 2 项）为例：

| 页码 | 页面 | 基准字数 | 说明 |
|---|---|---|---|
| 1 | 封面 | 70 | 自我介绍 + 题目，一句话进正题 |
| 2 | 编译领域积累 | 240 | **重点页**。四个栏目都要带到：论文级别、项目的评价、厂商的评价、编译优化的量化结果 |
| 3 | 需求分析 | 170 | 顺着「为什么重要 → 瓶颈 → 途径 → 软件栈」讲，不要并列报背景 |
| 4 | 研究现状 | 160 | 先讲整体是什么、缺什么，再各讲一个模块的职能和不足 |
| 5 | 研究概述 | 210 | **重点页**。只概括到子研究点，不把后面的方法讲完 |
| 6 | 研究内容一（技术） | 150 | 每个子问题讲「哪里不行、设计/提出了什么方法」 |
| 7 | 研究内容一（过程） | 130 | 按步骤讲，点出每步的产出 |
| 8 | 研究内容二（技术） | 150 | 同第 6 页 |
| 9 | 研究内容二（过程） | 130 | 同第 7 页 |
| 10 | 主要技术指标 | 130 | 指标要念准，数字不能含糊 |
| 11 | 研究成果及考核方式 | 120 | |
| 12 | 研究周期与进度安排 | 120 | |
| 13 | 经费预算 | 90 | |
| 14 | 结束语 | 70 | |

基准合计 1900 字，落在区间中段。研究内容多于或少于 2 项、或某项用了第 3 页时，按下列优先级调整：

1. **总量必须落在 1800–2000 字**，这是第一约束。
2. 重点页（第 2 页、第 5 页）不得低于 200 字，这是评审最关心的两页。
3. 封面与结束语各不超过 90 字，寒暄不占时间。
4. 需要腾字数时，从经费、成果考核、周期进度这类信息型页面里压，压缩比例不超过三分之一。

## 二、写法要求

- **评审口吻，不口语。** 旁白是讲给评审专家的，用「本项目」「我们」，按「在……方面」
  「从……来看」「综上」来组织。不把要点逐字念一遍，但也不解释成聊天：
  不写「卡住的是」「对症的一条路」「说白了」「所以呢」。
  旁白可以换说法，但**不许引入幻灯片和申请书里都没有的数字**。
- **页间要接得上，开场用模板的称呼。** 封面用「各位评审专家好，我是……」。
  第 2 页用「各位专家好，这一页汇报我们在……方向的积累」。其余页开头点明该页要回答的问题，
  不用「下面介绍……」，也不用同一句式起每一页。
- **术语第一次出现要落地。** 缩写、专有名词首次出现时给一句解释，之后直接用缩写。
- **数字读法要能开口念。** 百分比、金额、时间写成便于朗读的形式（"百分之十五"或"15%"均可，
  但同一份旁白保持一致）；关键指标念完整，不省略单位。
- **口径与申请书一致。** 旁白里的每个数字、每条结论都必须来自申请书原文，禁止四舍五入到
  走样、禁止把"预期"说成"已实现"、禁止添加申请书中没有的对比数据。
- **自称统一。** 全程用"我们"或"本课题"，不要一会儿"本项目"一会儿"我团队"。
- **收尾要稳，并且落到单位优势上。** 结束语旁白要呼应幻灯片上那句单位优势判断
  （编译方向的长期积累、质量保证与国产化保障能力、原型系统研制能力），最后用
  "请各位专家批评指正"这类常规表述收住，不写煽情句。

## 三、每页旁白的结构

正文页旁白按三段走，一段一句到两句：

1. **承上/点题**：这一页要回答什么问题。
2. **展开**：支撑该页要点的事实、方法或数据，只说要点里最重要的 1–2 条。
3. **落点**：一句话收在该页底部总结句的意思上（可以换说法，不要照抄总结句）。

封面页只有"问好 + 题目 + 一句总纲"；结束语页只有"一句总括 + 致谢"。

## 四、交付前自检

逐条核对，缺一不可：

- [ ] 逐页统计字数，总和落在 1800–2000 字。
- [ ] 重点页（第 2、5 页）各不少于 200 字。
- [ ] 封面、结束语各不超过 90 字。
- [ ] 每页旁白都标注了本页字数，末尾给出总字数与折算时长。
- [ ] 通读一遍：有没有口语（「卡住」「对症」「说白了」「所以呢」）、有没有同构开场、
      页与页之间是否接得上。书面表述（「旨在」「予以」）不是问题，不必改掉。
- [ ] 对照下面的「逐页旁白框架」：该页框架里列出的要素，旁白里都要有；缺了就补，
      不另起一套说法。
- [ ] 旁白里的数字与申请书原文逐个核对过。
- [ ] 按 200 字/分钟折算，总时长在 9–10 分钟之间。

`build_ppt.py` 会在生成时打印每页旁白字数、总字数与折算时长，直接拿它核对前四条；
后三条需要通读，脚本查不了。

## 五、逐页旁白框架

框架只规定一页讲哪几件事、按什么顺序，不规定用什么词。事实和数字仍只取申请书和用户给出的材料。
第 1、2、4、5、6、8、13、14 页的骨架来自 `assets/template.pptx` 的备注；
第 3、7、9、10、11、12 页模板备注是空的，骨架取自
`skills生成后的人工修改.pptx` 的备注结构。

| 页 | 按这个顺序讲 |
|---|---|
| 1 封面 | 各位评审专家好，我是〈单位〉〈姓名〉。今天汇报〈题目〉，重点介绍问题、方案与考核安排 |
| 2 积累 | 各位专家好，这一页汇报〈方向〉积累。入职年份与从业年限；该方向得到哪些专项的长期支持；论文按团队口径给出级别和篇数；合作厂商有哪些、成果落地在哪；开发了多少套、多少项优化、含金量最高的一个量化结果；技术演进的三个层次；综上，落到研制基础 |
| 3 需求 | 对象已经用在哪里；瓶颈是什么，有量化依据就念出来；哪条途径对症；现有软件栈按什么假设设计、与目标架构差在哪；因此需要什么样的软件栈 |
| 4 现状 | 这个软件栈是什么、包含哪两个部件、各自负责什么；现有工作没适配目标架构的哪一点；按维度对比差异；每个部件的不足，点明这正是本项目要突破的 |
| 5 概述 | 核心目标一句话，加上做到之后的意义；两项内容只点到子研究点（提出什么、建立什么、设计什么），不讲做法 |
| 6 技术（一） | 先给这项内容一句话：面向什么特性、形成什么体系；再按子问题讲，每个子问题是「它起什么作用；传统做法缺什么；我们设计或提出什么方法，覆盖哪些，解决什么」。方法要点出名字，不说「这是创新点」 |
| 7 过程（一） | 按流程图的步骤顺序讲，点明每一步的输入和产出，最后一句说清步骤之间怎么前后衔接 |
| 8 技术（二） | 同第 6 页 |
| 9 过程（二） | 同第 7 页 |
| 10 指标 | 指标按可验证的能力念，数字和口径与申请书一致，不另加百分比 |
| 11 成果 | 每类成果说交付什么、用什么方式考核，最后说提交哪里、如何留档 |
| 12 周期 | 总周期和阶段数，然后逐段说该段做什么、验证什么 |
| 13 经费 | 总额；各科目金额和用途；哪一项是主要支出；收益和不可预见费的数值 |
| 14 结束语 | 本单位在该方向的长期积累、已有研发与应用经验、对本课题的研制基础；感谢各位专家，请批评指正 |
