# 论文 PDF 转总结汇报 PPT（pdf2ppt）

把一篇论文 PDF 变成一套 15 分钟内讲完的汇报材料：**可编辑的论文总结 pptx**
（旁白在 PowerPoint 备注页）+ **逐页旁白稿 md/docx**。页面按固定七节组织，
图优先用论文原图，每个内容页图文都有；听众按「学术专家 + 小白」混合定位。

内容只做「提炼与搬运」：页面与旁白里的每个数字、每个机制描述、每个引用编号
都必须能在论文原文里找到出处，禁止编造。

## 工作流程

六个阶段顺序推进，产物落盘后再进下一阶段。

### 阶段 0：环境与目录

- 虚拟环境与脚本：`PY=<skill目录>/.venv/bin/python`，`S=<skill目录>/scripts`
  （skill 目录即本 SKILL.md 所在目录）。`.venv` 缺失时按 `requirements.txt` 用 uv 重建。
- 工作目录：在 PDF 所在目录下建 `<PDF文件名去后缀>_ppt/`：

```
<PDF名>_ppt/
├── extract/            # 阶段1产物：text.md、pages/、figures/、figures.json、meta.json
├── figs/               # 本 PPT 实际引用的图（从 extract/figures/ 复制；可再裁剪）
├── content.json        # 阶段4产物：逐页内容 + 旁白
├── paper-ppt-<简称>-<YYYYMMDD>.pptx    # 文件名一律英文，简用论文英文缩写
├── narration-<简称>-<YYYYMMDD>.md / .docx
└── preview/            # 逐页预览图
```

### 阶段 1：深读底稿——先走 paper-reader

**优先调用 paper-reader 技能**（`~/.claude/skills/paper-reader`，用 Skill 工具或按其
SKILL.md 执行）：让它把本 PDF 的 `summary.md` + `extract/` 产出到**本技能的工作目录**
`<PDF名>_ppt/`（两技能的 extract 产物结构完全共用）。理由：

- paper-reader 的七章总结与本技能七节结构一一对应，可直接当深读底稿；
- 其数字已过数字溯源校验、术语首现已带白话解释——白话解释可直接搬进旁白；
- 避免同一篇 PDF 全文深读两遍。

paper-reader 不可用（技能缺失/调用失败）时退回本技能自带管线：

```bash
$PY $S/extract_pdf.py <论文.pdf> --out <工作目录>
```

产出带页码标记的全文 `extract/text.md`、每页预览图、按图注裁剪的 200 dpi 图表 PNG
及 `figures.json`（含像素宽与宽高比）。扫描版（提示可提取文字很少）改为用 Read 逐页看
`extract/pages/`；`crop: null` 的条目引用前必须人工确认。

### 阶段 2：核对与补读（基于 summary.md）

以 `summary.md` 为底稿（走退回管线时通读 `extract/text.md`，长文分段读完，不许跳读），
逐项确认下面七问（写 content.json 前自检），并 Read 论文关键页核对图的理解：

1. 研究背景与逻辑链，如何导向研究问题；
2. 核心研究问题一两句话；动机示例/数据说明什么缺口；
3. 已有研究分几类，每类原理与不足（对应哪些参考文献）；
4. 本文 idea 与关键洞察——**为什么它能解决之前解决不了的问题**；
5. 具体实施步骤（模块划分、机制流程）；
6. 实验目标、平台、负载、基线、指标、结果数字与分析；
7. 原文结论、局限与可改进空间。

**发表信息**：从 PDF 首页/页眉/元数据确认会议或期刊与年份；级别与影响力
（CCF 分级、录用率）按公认常识描述，拿不准就联网核实，禁止编造；
确无会议标注（arXiv 预印本）就如实写预印本。概述页与封面要用。

### 阶段 3：选图与备图

**先读 `references/figure-spec.md`**。把要用的原文图从 `extract/figures/` 复制到 `figs/`
（保留 figN.png/tabN.png 名）；逐张检查清晰度（像素宽 ÷ 7.15 ≥ 110 DPI），
不足的按原结构重排或重画。必选图：

- 研究问题页的**动机示例图**、方法原理页的**总体框架图**、实验页的**主结果图**——
  论文有就必须用原文图；
- 现状页：自绘 framework 分类图 + 原文对比 Table（或 table 重排）；
- 论文没有流程图时，方法步骤页用 flow 按原文机制自绘。

### 阶段 4：写 content.json（逐页内容 + 旁白）

**先读 `references/content-spec.md` 与 `references/narration-spec.md`**，
再按默认 12 页规划（允许 11–15 页）写 `content.json`：
七节齐全有序，五.方法 ≥2 页（原理 + 步骤），六.实验 ≥2 页。

写作形式（check_ppt 强制）：

- **标题式要点**：一级 `标签：短语主句`（≤20 字宽，禁句号）+ 二级短说明（≤22 字宽），
  层级 ≤2；完整句子一律放旁白——**页面上杜绝大段文字**（参照 proposalword2ppt）。
- **正文版式**（build_ppt 自动排，spec 见 template-spec 第三节）：一级 `▶` 18 磅、
  二级 `●` 16 磅（小 2 号）；二级文字比一级文字再进 2 个字；下划线只给标签（含冒号），
  主句与二级行不带。
- **红粗强调**：`{{重点}}` 标红加粗（C00000），每个内容页至少 1 处，
  用在关键数字/方法名/结论词；`**文字**` 为加粗。
- **页面饱满**：每页 4–6 条要点为宜；单图太小、版面空时给第二组图（原文次要图、
  重排 table、自绘 bar/flow 都行）——单图槽版式给 2~3 组图会自动上下切分图槽。
- 旁白按逐页字数预算写，总量 2600–3000 字（15 分钟内）。
- content.json 契约见 `references/template-spec.md` 第五节；**输出文件名一律英文**。

### 阶段 5：生成、校验、出 docx

```bash
$PY $S/build_ppt.py --content content.json --out paper-ppt-<简称>-<YYYYMMDD>.pptx \
        --narration-out narration-<简称>-<YYYYMMDD>.md
$PY $S/check_ppt.py paper-ppt-<简称>-<YYYYMMDD>.pptx --content content.json        # 门禁1
$PY $S/check_narration.py narration-<简称>-<YYYYMMDD>.md --extract extract         # 门禁2
$PY $S/preview_slides.py --pptx paper-ppt-<简称>-<YYYYMMDD>.pptx --out-dir preview
$PY $S/build_docx.py narration-<简称>-<YYYYMMDD>.md
```

- 两个门禁**错误清零**才算过（警告逐条确认，确属合理可放行并说明）；
  `[校验]` 行按提示改 content.json 后**重新生成**，不要手改 pptx。
- 逐页看 preview：图读不读得清、图文挤不挤、有没有占位残留、一边满一边空。
  **没看过的页不算完成**；只能出近似预览时在交付说明里注明。
- docx 生成后核对输出统计（段落数与 md 一致）。

## 交付物（三样，同一目录，文件名全英文）

1. `paper-ppt-<简称>-<YYYYMMDD>.pptx`：可放映可编辑，旁白在备注页；
2. `narration-<简称>-<YYYYMMDD>.md` + `.docx`：逐页旁白，含总字数与折算时长；
3. 对话里给出：逐页大纲（标题/要点/图表来源/总结句）+ 生成说明
   （哪些页用了原文哪张图、哪些自绘、发表信息依据、遗留问题）。

## 检查点清单（交付前逐条自查）

- [ ] 七节齐全有序：一.概述 / 二.背景 / 三.问题 / 四.现状 / 五.方法(≥2页) / 六.实验(≥2页) / 七.总结
- [ ] 概述页按固定顺序讲全：**发表信息（年份+会议/期刊+级别+影响力）**→背景→问题→已有方法不足→本文方法→结果→意义
- [ ] 封面副标题含发表信息；题目是论文中文译名
- [ ] 背景页要点是逻辑链（不是并列背景堆砌）
- [ ] 问题页 1–2 句核心问题 + 动机示例（原文示例图用上了）
- [ ] 现状页每类方法「原理→不足」且**带原文引用编号**，并结合动机示例说明不足
- [ ] 方法页有**原文总体框架图**；步骤页有机制图或自绘 flow；讲了为什么能解决之前解决不了的问题
- [ ] 实验页覆盖：目标（回答什么问题）、平台、指标、比对方法、原文图表、**结论与分析**（不只念数字）
- [ ] 总结页三类要点齐全：一句话总结 + 不足与改进 + **启发**（关键项）
- [ ] 每个内容页图文都有；正文 ≥3 条要点；字号 ≥12 磅；无占位残留
- [ ] **标题式要点**：短语无句号、层级 ≤2、无大段文字；关键数字/方法名/结论词有 `{{红粗}}`（每页 ≥1 处）
- [ ] **正文版式**：一级 ▶ / 二级 ● 项目符号齐全；二级缩进 = 一级 + 2 字、字号小 2 号；
      下划线只在标签（含冒号）上，主句与二级行无下划线
- [ ] **页面饱满**：无「图小字少一片空」的页——稀疏页补第二组图（自动上下切分）或加要点
- [ ] 原文图清晰够大（自动去白边 + 按实际比例贴边放置，无大块白板）
- [ ] 最后一页是**要点回顾**（Take-away + 出处 + 居中「感谢聆听」），无「欢迎批评指正」类套话
- [ ] 输出文件名全英文（paper-ppt-…/narration-…）
- [ ] 旁白总量 2600–3000 字（≤15 分钟）；概述页是完整一段；总结页旁白讲了不足与启发
- [ ] 所有数字、机制、引用编号可溯源到原文（check_narration 数字溯源警告逐条确认）
- [ ] 两个门禁错误清零；preview 逐页看过
- [ ] md → docx 已生成；模板样式未被改动

## 硬性规则

1. 内容严格来自论文原文；发表信息不确定就核实或如实标注，禁止虚构。
2. 每页图文都有，图优先用原文图表；自绘图准确反映论文机制。
3. 旁白是讲解口吻（专家+小白混合听众），术语首现给白话解释，数字与原文一致。
4. 门禁未过不得交付；改内容改 content.json 再重新生成，不手改 pptx。
5. 不修改论文 PDF 与 extract/ 产物；figs/、content.json 与三个交付文件是唯一输出。
