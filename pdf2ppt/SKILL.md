# 论文 PDF 转总结汇报 PPT（pdf2ppt）

把一篇论文 PDF 变成一套 15 分钟内讲完的汇报材料：**可编辑的论文总结 pptx**
（旁白在 PowerPoint 备注页）+ **逐页旁白稿 md/docx**。页面按固定八节组织、
末尾附参考文献页，图优先用论文原图，每个内容页图文都有；听众按「学术专家 + 小白」
混合定位。目标只有一个：**读者/听众看每一页都清楚明白**——页面自己能看懂，旁白再讲透。
**生成不是终点**：出片后必须走迭代检查（阶段 6），把版面与讲解问题修完才算交付。

内容以「提炼与搬运」为底：页面与旁白里的每个数字、每个机制描述、每个引用编号
都必须能在论文原文里找到出处，禁止编造。唯一例外是示例说明页的自构数值
（须口播/标注「示例取值」，推演逻辑与论文机制严格一致）。

## 工作流程

七个阶段顺序推进：0–4 备稿，5 生成，6 迭代检查与修复（**循环，直到全部问题清零**）。

### 阶段 0：环境与目录

- 虚拟环境与脚本：`PY=<skill目录>/.venv/bin/python`，`S=<skill目录>/scripts`
  （skill 目录即本 SKILL.md 所在目录）。`.venv` 缺失时按 `requirements.txt` 用 uv 重建。
- 工作目录：在 PDF 所在目录下建 `<PDF文件名去后缀>_ppt/`：

```
<PDF名>_ppt/
├── extract/            # 阶段1产物：text.md、cover.png、pages/、figures/、figures.json、meta.json
├── figs/               # 本 PPT 实际引用的图（从 extract/figures/ 复制；可再裁剪/加标注）
├── content.json        # 阶段4产物：逐页内容 + 旁白
├── <论文题目>-slide.pptx            # 论文题目取 meta.json 的 title_guess，清理成安全文件名
├── <论文题目>-旁白.md / .docx
└── preview/            # 逐页预览图
```

- 文件名清理规则与 paper-reader 一致：空格换 `_`，`/\:*?"<>|` 换 `-`，去首尾标点，
  超 60 字符在词边界截断；再拼 `-slide.pptx` / `-旁白.md`（check_ppt 校验后缀）。

### 阶段 1：深读底稿——先走 paper-reader

**优先调用 paper-reader 技能**（`~/.claude/skills/paper-reader`，用 Skill 工具或按其
SKILL.md 执行）：让它把本 PDF 的 `<论文题目>_summary.md` + `extract/` 产出到**本技能的
工作目录** `<PDF名>_ppt/`（两技能的 extract 产物结构完全共用）。除了避免同一篇 PDF
全文深读两遍，paper-reader 的产物对本技能有四个直接可复用的点：

- **`<论文题目>_summary.md` 的示例说明章**：它已用一个小例子把核心方法逐步推演到
  结果并配了流程图——本技能「六.示例说明」页直接取材；
- **`extract/cover.png`**：论文第 1 页顶部截图（题目/作者/期刊信息）——概述页固定嵌入；
- **`meta.json` 的 `link_candidates`**：第 1 页扫出的 arXiv/DOI 候选外链，**核实确属本文后**
  写进概述页与旁白；确无公开链接就如实写「未找到公开链接」，禁止编造；
- **`meta.json` 的 `title_guess`**：交付文件命名的依据；
- 其数字已过数字溯源校验、术语首现已带白话解释——白话解释可直接搬进旁白。

paper-reader 不可用（技能缺失/调用失败）时退回本技能自带管线（产物结构相同）：

```bash
$PY $S/extract_pdf.py <论文.pdf> --out <工作目录>
```

产出带页码标记的全文 `extract/text.md`、每页预览图、`cover.png`、按图注裁剪的
200 dpi 图表 PNG 及 `figures.json`（首个条目即 cover，含像素宽与宽高比）、
`meta.json`（title_guess + link_candidates）。扫描版（提示可提取文字很少）改为用
Read 逐页看 `extract/pages/`；`crop: null` 的条目引用前必须人工确认。

### 阶段 2：核对与补读（基于总结稿）

以总结稿为底稿（走退回管线时通读 `extract/text.md`，长文分段读完，不许跳读），
逐项确认下面九问（写 content.json 前自检），并 Read 论文关键页核对图的理解：

1. 研究背景与逻辑链，如何导向研究问题；
2. 核心研究问题一两句话；动机示例/数据说明什么缺口；
3. 已有研究分几类，每类**原理**与由原理推出的**不足**（对应哪些参考文献）——
   不足必须是原理层面的天花板，不是「没做好」；
4. 本文 idea 与关键洞察——**为什么从原理上它能解决传统方法解决不了的问题**；
5. 具体实施步骤（模块划分、机制流程）；方法章出现的关键名词，论文里有没有
   对应的示意/示例图；
6. 实验目标、平台、负载、基线、指标、结果数字与分析；
7. 原文结论、局限与可改进空间；
8. 论文是否自带运行示例/动机示例（六.示例说明页的取材：有就用原文的，
   没有就自构一个能贯穿全文方法的小例子）；
9. 论文外网链接（核对 `link_candidates` 与题目对应，必要时联网检索）。

**发表信息**：从 PDF 首页/页眉/元数据确认会议或期刊与年份；级别与影响力
（CCF 分级、录用率）按公认常识描述，拿不准就联网核实，禁止编造；
确无会议标注（arXiv 预印本）就如实写预印本。概述页与封面要用。

### 阶段 3：选图与备图

**先读 `references/figure-spec.md`**。把要用的原文图从 `extract/figures/` 与
`extract/cover.png` 复制到 `figs/`（保留 figN.png/tabN.png 名）；逐张检查清晰度
（像素宽 ÷ 7.15 ≥ 110 DPI），不足的按原结构重排或重画。必选图：

- **概述页固定用 `cover.png`**（论文首页截图：题目、作者、期刊/会议信息）；
- 研究问题页的**动机示例图**、方法原理页的**总体框架图**、实验页的**主结果图**——
  论文有就必须用原文图；
- 现状页：自绘 framework 分类图 + 原文对比 Table（或 table 重排）；
- **示例说明页的示例流程图**：论文有运行示例图就用原文的；没有就自绘 `flow`
  （steps 带 children），节点文字写「步骤：输入→输出（数据形态）」；
- 论文没有流程图时，方法步骤页用 flow 按原文机制自绘。

**图的标注**（解决「直接从 PDF 拿图、读者看不懂」的问题）：原文图里英文术语多、
结构复杂时，用 PIL 在 `figs/` 的复制件上叠中文标注（圈注关键区域、箭头+术语翻译、
一两句关键结论），存成 `figN_annotated.png` 再嵌入；标注不遮关键数据。不加标注的图，
也要靠 caption 一句话与页面要点把「这张图表达什么」讲出来（见 figure-spec）。

### 阶段 4：写 content.json（逐页内容 + 旁白）

**先读 `references/content-spec.md` 与 `references/narration-spec.md`**，
再按默认 14 页规划（允许 13–17 页）写 `content.json`：
八节齐全有序，五.方法 ≥2 页（原理 + 步骤），六.示例说明 1–2 页，七.实验 ≥2 页，
倒数第二页是**参考文献页**（kind=refs，条目与全片引用编号一一对应）。

写作形式（check_ppt 强制）：

- **标题式要点**：一级 `标签：短语主句`（≤20 字宽，禁句号）+ 二级短说明（≤22 字宽），
  层级 ≤2；完整句子一律放旁白——**页面上杜绝大段文字**（参照 proposalword2ppt）。
- **正文版式**（build_ppt 自动排，spec 见 template-spec 第三节）：一级 `▶` 18 磅、
  二级 `●` 16 磅（小 2 号）；二级文字比一级文字再进 2 个字；下划线只给标签（含冒号），
  主句与二级行不带。**文字字体字号固定**，不自适应；放不下就减字数、砍二级行。
- **红粗强调**：`{{重点}}` 标红加粗（C00000），每个内容页至少 1 处，
  用在关键数字/方法名/结论词；`**文字**` 为加粗。
- **页面饱满**：每页 4–6 条要点为宜；单图太小、版面空时给第二组图（原文次要图、
  重排 table、自绘 bar/flow 都行）——单图槽版式给 2~3 组图会自动上下切分图槽。
- **图文互释**：每张嵌入的图，页面要点中至少一条与它相关（解释关键元素/术语/结论），
  **旁白必须讲这张图**（是什么、怎么看、说明什么）——只放图不解释算不合格
  （check_ppt 强制）。原文图由脚本自动去白边并按长宽比在图槽内贴边放置，
  选图时优先挑宽高比接近 2:1（图槽比例）的图，细长图裁段或拼图。
- 旁白按逐页字数预算写，总量 2600–3000 字（15 分钟内）；示例页自构数值口播
  「示例取值」，check_narration 的数字溯源警告须逐条确认为示例取值后放行。
- content.json 契约见 `references/template-spec.md` 第五节。

### 阶段 5：生成与三道门禁

```bash
$PY $S/build_ppt.py --content content.json --out <论文题目>-slide.pptx \
        --narration-out <论文题目>-旁白.md
$PY $S/check_ppt.py <论文题目>-slide.pptx --content content.json        # 门禁1：结构与内容
$PY $S/check_narration.py <论文题目>-旁白.md --extract extract         # 门禁2：旁白
$PY $S/preview_slides.py --pptx <论文题目>-slide.pptx --out-dir preview
$PY $S/inspect_preview.py preview --content content.json                # 门禁3：预览版面
$PY $S/build_docx.py <论文题目>-旁白.md
```

- 三道门禁**错误清零**才算过（警告逐条确认，确属合理可放行并说明）；
  `[校验]` 行按提示改 content.json 后**重新生成**，不要手改 pptx。
- 门禁覆盖：门禁1 = 八节结构与参考文献对应、图文都有、图文不重叠、字号下限、
  要点形式、嵌入图有效 DPI、有图必被旁白讲、概述页网址；门禁2 = 旁白预算/格式/
  口语/数字溯源；门禁3 = 预览逐页的标题/正文/图/总结区覆盖、图偏小与整块空白。
- docx 生成后核对输出统计（段落数与 md 一致）。

### 阶段 6：迭代检查与修复（循环，直到全部问题清零）

生成只是初稿。**逐页过下面的清单 → 发现问题 → 修复 → 重新生成 → 重跑三道门禁**，
循环到机械检查全绿、内容级自检逐页通过为止；每轮迭代记录改了什么。
修复只改三个地方：`content.json`（要点/旁白/图选择/切分方式）、`figs/`（换图/裁剪/
加中文标注）、自绘图 spec——**绝不手改 pptx**。

**机械检查**（脚本，错误必须清零）：

1. 图文不重叠、图内元素不重叠不截断、正文不溢出框（门禁1 + build 审计）；
2. 每个内容页图文都有、有图必被旁白讲到（门禁1）；
3. 图区/正文区无整块空白、单图页图不过小、比例协调（门禁3 + 逐页看 preview）；
4. 嵌入原图有效 DPI ≥110；95–110 偏软须在生成说明注明，<95 换图或重排（门禁1）；
5. 参考文献页编号与全片引用一一对应（门禁1）；
6. 旁白总量 2600–3000 字、数字可溯源（门禁2）。

**内容级自检**（逐页对照 preview 与旁白稿，语义判断，这是机器替不了的）：

1. **每页讲清楚了吗**：这页要让听众记住什么？要点、图、旁白三处是否合力讲透；
   尤其每张图——旁白解释了它是什么/怎么看/说明什么吗；图中英文术语多、结构复杂时，
   是否该在图外叠中文标注（`figN_annotated.png`）或补一张小图才看得懂；
2. **咬合链对得上吗**（四页连读）：三.的问题与难点 → 四.每类方法「原理→由原理推出
   的不足」→ 五.每个机制接住哪条不足、为什么原理上能解决 → 示例页推演的正是这套
   对策 → 七.实验收益来源与之呼应；口径不一致（两张皮）必须改齐；
3. **版面协调吗**：逐页看 preview——文字与图/表比例是否协调、有没有大片空白（补
   第二组图/加标注图/加解释要点）、有没有越界或挤压（减要点/砍二级行/换更合适的图）；
4. **听众跟得上吗**：术语首现有白话解释吗；每页旁白开场承接上一页吗；示例页是否
   逐步推演、每步的输入输出与数据形态都落地了吗；
5. **口径诚实吗**：示例取值/自析是否标注；数字与原文一致；不足与启发注明出处口径。

**退出条件**（全部满足才算交付）：三道门禁错误清零、警告逐条确认放行；内容级自检
1–5 逐页通过；preview 每页都看过（本机看图受限时用 PIL 程序化检测补足并在交付说明
注明）；本轮迭代不再产生新问题。

## 交付物（三样，同一目录）

1. `<论文题目>-slide.pptx`：可放映可编辑，旁白在备注页；
2. `<论文题目>-旁白.md` + `.docx`：逐页旁白，含总字数与折算时长；
3. 对话里给出：逐页大纲（标题/要点/图表来源/总结句）+ 生成说明
   （哪些页用了原文哪张图、哪些图加了中文标注、哪些自绘、发表信息与论文网址依据、
   示例是原文的还是自构的、遗留问题）。

## 检查点清单（交付前逐条自查）

- [ ] 八节齐全有序：一.概述 / 二.背景 / 三.问题 / 四.现状 / 五.方法(≥2页) /
      六.示例说明(1–2页) / 七.实验(≥2页) / 八.总结
- [ ] 概述页按固定顺序讲全：**发表信息（年份+会议/期刊+级别+影响力）**→背景→问题→
      已有方法不足→本文方法→结果→意义，并有**论文网址**（核实后的 arXiv/DOI；
      确无就如实写「未找到公开链接」）
- [ ] 概述页嵌入 `cover.png`（论文首页截图），旁白指着它讲题目/作者/出处
- [ ] 封面副标题含发表信息；题目是论文中文译名
- [ ] 背景页要点是逻辑链（不是并列背景堆砌），版面不空（单图小就补第二组图或加标注）
- [ ] 问题页 1–2 句核心问题 + 动机示例（原文示例图用上了）
- [ ] 现状页每类方法「**原理→由原理推出的不足**」且**带原文引用编号**，并结合动机
      示例说明传统方法面对它会怎样失效
- [ ] 方法页有**原文总体框架图**；步骤页有机制图或自绘 flow；**从原理上讲清为什么
      本文方法能解决而传统方法不行**（页面文字、图内标注或旁白，至少占其一）
- [ ] 方法章关键名词配有示例图/示意图（原文有就用，没有可自绘），空洞页面已补图或补解释
- [ ] 示例说明页：论文有示例用原文的，没有则自构小例子**贯穿全文核心方法逐步推演到
      结果**，流程图节点写「步骤：输入→输出（数据形态）」；自构数值标注/口播「示例取值」；
      旁白逐步对应推演
- [ ] 实验页覆盖：目标（回答什么问题）、平台、指标、比对方法、原文图表、**结论与分析**
      （不只念数字）
- [ ] 总结页三类要点齐全：一句话总结 + 不足与改进 + **启发深挖**（前提假设限制、
      未考虑的因素/场景、换场景、与 xxx 融合、论文未介绍或定死但关键的设计点；
      注明原文口径还是「自析」）
- [ ] 每个内容页图文都有；**每张图旁白都讲了**（是什么/怎么看/说明什么），页面要点或
      图标注解释了图中关键术语；正文 ≥3 条要点；字号 ≥12 磅；无占位残留
- [ ] **标题式要点**：短语无句号、层级 ≤2、无大段文字；关键数字/方法名/结论词有
      `{{红粗}}`（每页 ≥1 处）
- [ ] **正文版式**：一级 ▶ / 二级 ● 项目符号齐全；二级缩进 = 一级 + 2 字、字号小 2 号；

## 硬性规则

1. 内容严格来自论文原文；发表信息与论文网址不确定就核实或如实标注，禁止虚构。
   示例说明页自构数值除外，但必须标「示例取值」且推演逻辑与论文机制一致，
   不得为了例子改变方法。
2. 每页图文都有，图优先用原文图表；自绘图准确反映论文机制，不加「自绘」标识。
3. **每张图都要被讲清楚**：旁白必须解释这张图是什么/怎么看/说明什么；页面要点或
   图内中文标注至少解释图中关键术语与结论——只放图不解释算不合格。
4. 旁白是讲解口吻（专家+小白混合听众），术语首现给白话解释，数字与原文一致。
5. **生成后必须迭代检查**（阶段 6）：机械检查 + 内容级自检的问题修完、三道门禁
   错误清零才可交付；改内容改 content.json / figs 再重新生成，绝不手改 pptx。
6. 不修改论文 PDF 与 extract/ 产物；figs/、content.json 与三个交付文件是唯一输出。
