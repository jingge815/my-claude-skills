# 旁白规范（25–30 分钟，讲清优先）

配套 `references/content-spec.md`。旁白写到 `content.json` 的 `narration` 字段
（build 时自动写入 PPT 备注页并导出旁白稿 md）。

听众是**零基础大众**：旁白是讲解稿，不是提纲串词。每个页面要点都要在旁白里
讲透——是什么、为什么、跟上下文什么关系；关键概念首次出现给白话定义（可加类比）；
不许为了精简字数写成电报句（「橙是注意力层」→「橙色区域是注意力层」）。

## 1. 总量与预算

按每分钟 200 字折算，**总字数 5500–6500 字（约 25–30 分钟），硬上限 7000**。
写完必须统计（check_narration.py 机械校验）。

默认 20–24 页的逐页预算（合计约 6000 字）：

| 页 | 字数 | 说明 |
|---|---|---|
| 封面 | 80–120 | 问好 + 论文题目 + 一句话定位 |
| 一.论文概述 | 320–400 | **完整一段**，按固定顺序讲（网址不念，只放页面） |
| 二.研究背景（1–2 页） | 300–380/页 | 沿逻辑链讲，落到缺口；指着背景图讲 |
| 三.研究问题（1–2 页） | 280–360/页 | 先念核心问题，再带动机示例（图要讲透），难点讲清 |
| 四.传统研究现状（2–3 页） | 280–380/页 | **第一句总起「已有研究分为 N 类」**；每类：原理展开讲（小白能懂）→ 由原理推出的不足 → 引用编号 |
| 五.方法：核心概念（若有） | 280–380 | 把 2–3 个前置概念用白话+类比讲清，小白才能跟上下文 |
| 五.方法：核心原理 | 300–400 | 重点页：为什么以前做不到、本文原理上为什么行 |
| 五.方法：步骤页（每页） | 260–340 | 讲机制怎么运转，配图讲，每个关键名词借图解释 |
| 六.示例说明（2–4 页） | 300–420/页 | 第 1 页整体思路+流程总览；后续页逐步推演，**每步带衔接句** |
| 七.实验页（3–4 页） | 280–380/页 | 先说要回答什么问题，再讲设置一句、结果与分析；图表按第 3 节五步模板 |
| 八.总结 | 300–400 | 一句话总结 + 不足与改进 + **第一人称启发** |
| 参考文献页 | ≤80 | 固定一句：「下面是论文的相关参考文献，感兴趣的可以按图索骥」，**不逐条念、不说别的** |
| 要点回顾页 | 60–100 | 一句话 take-away 收束 + 报论文出处 +「感谢聆听」 |

方法/实验/示例页数增加时按此单页预算增减，总量卡在 5500–6500。

## 2. 口吻与表达硬规则

- 讲解口吻：用「本文」「我们来看」；不写聊天腔（禁止「卡住」「对症」「说白了」「所以呢」「咱们」「呃」）。
- **说人话（check_narration 强制）**：句子主谓宾完整、读出声顺口；禁止电报式省略——
  「橙是注意力层」「红是放缓冲裸片」这类必须写成「橙色区域是注意力层」「红色表示放在
  缓冲裸片上」；色词必须带「色/区域/柱/线」等量词后才能接「是/代表/表示」。
- **旁白不念网址**：URL、arXiv 编号、DOI 只放页面要点，解说词禁止出现
  （check_narration 强制）。
- 术语第一次出现给白话解释（如「KV 缓存——就是推理过程中间结果的缓存」），
  之后再直接用；解释不了的概念就展开讲一两句，不跳过。
- 每页开场承接上一页（「看完了背景，我们再看…」），不要每页都用同一个开场。
- 数字与论文原文逐个一致；倍数、百分比不许改动或四舍五入到别的数。
  **例外**：六.示例说明的自构数值须口播「示例取值」，check_narration 的数字溯源
  警告逐条确认为示例取值后放行。

## 3. 图表讲解五步模板（每张图/表必须按此顺序讲，check_narration 校验）

1. **总体句**：这张图/表总体在干什么——「图 15 对比的是四种方法在不同批量下的端到端时延」；
2. **坐标与图例**：横轴是什么（从左到右怎么变）、纵轴是什么（单位）、每种颜色/每组柱/每列代表什么；
3. **比对对象与指标方向**：比的是哪些方法，这个指标**越大越好还是越小越好**；
4. **总体结论一句**：看整体趋势先说结论（谁赢、差多少量级）；
5. **1–2 个支撑细节**：挑最关键的一两处（某根柱、某条线）展开，说清原因。

色词规则同第 2 节；图中英文术语随讲随翻。图多页连讲时每张图都走一遍五步，
不许「同样的图例上一页讲过了」就不讲——每页听众可能刚进来。

## 4. 概念解释要求

- 方法依赖的前置概念（数据结构、调度单元、指标名）在首次出现的那一页旁白里给
  白话定义，格式「术语——就是大白话（，类比：像…一样）」；
- 概念之间有依赖时按依赖顺序讲，别让听众拿着没定义的概念听机制；
- 解释篇幅不计入"精简"考量——讲清优先。

## 5. 各页旁白要点（按页型）

- **封面**：问好、论文题目（中文译名，可带英文原题）、一句话定位（「这是一篇做 xxx 的论文」）。
- **研究背景**：沿逻辑链讲，每环一两句，最后一句明确「这就带来了一个问题」；
  背景图要讲（这张图画的是什么架构、哪些部分和本文有关）。
- **研究问题**：把页面上那句核心问题完整念出来（这是全文最该被记住的一句话），
  然后用动机示例/图把问题讲疼——动机图必须讲（示例是什么、卡在哪一步）。
- **研究现状**：第一句「已有研究分为 N 类」；每类点名代表工作（「AttAcc 这类工作把
  KV 缓存当作大张量静态映射」），讲**原理**（小白能懂的展开），再**由原理推出不足**
  （它天生做不到什么，为什么），不是只说「有不足」；每页收尾一句总括。
- **方法页**：原理页把「为什么以前做不到、本文怎么做到」**在原理层面讲透**
  （这是专家最关心的）；步骤页讲机制怎么运转，配图讲（「大家看左边的图，…」）；
  出现关键名词时，用一句话借图解释。
- **示例说明页**：第 1 页先交代示例设定（输入、规模、为什么小），然后**整体流程
  一句话总览**（「整个流程分四步：先…再…然后…最后…」）；后续页**按流程逐步推演**：
  「第一步输入是…，经过…，输出是…，这时数据长这样…；**这个输出会作为下一步的
  输入，送到…**」——每步必带衔接句（check_narration 强制）；最后给推演结果与验证点。
  自构数值口播「示例取值」。
- **实验页**：先说这组实验回答什么问题，再讲设置一句、结果数字、分析（收益从哪来）；
  实验图表按第 3 节五步模板讲，不逐个念数。
- **总结页**：先一句话总结全文；再讲不足与改进（每条一句）；**最后讲启发——
  第一人称感受式**：「通过这次阅读，给我的启发是…」，把为什么值得做说透，
  注明原文口径还是自析。禁「启发两条/三点/如下」列举式开头（check_narration 强制）。
- **要点回顾页**：一句话 take-away 收束全场（呼应页面红粗词），报一遍论文出处
  （英文原题 + 会议/期刊或 arXiv 编号 + 网址——这里只出现在页面信息行，旁白报
  「出处和网址都在屏幕上」即可），最后一句「以上就是本次分享，感谢聆听」。

## 6. 旁白稿 md 格式（build_ppt --narration-out 自动生成）

```markdown
# 《题目》论文总结PPT旁白稿

> 共 22 页（含封面与结束页）；按每分钟 200 字折算，约 28 分钟。

## 第1页 封面

　　各位老师好，……

## 第2页 一.论文概述

　　（旁白正文，一段或两段，每段以两个全角空格开头）

**旁白总字数：6012 字（约 30.1 分钟）**
```

该格式与 `build_docx.py` 的方言一一对应，直接转 docx；
机械校验用 `check_narration.py`（页面连续、八节结构、预算、格式、口语、色词、
网址、现状/示例/启发话术、图表要素、数字溯源）。

写完不是终点：旁白稿要跟着阶段 6 的迭代检查一起改——每张图都按五步讲了吗、
术语首现有白话解释吗、每页开场承接上一页吗、句子通顺吗（朗读一遍）、
咬合链口径一致吗；发现问题改 content.json 重新生成，不直接改 md。
