# 逐页内容规范（八节结构）

本文档定义论文总结 PPT 每一页写什么、几个要点、什么句式。写 `content.json` 前必读；
与 `references/narration-spec.md`（旁白）、`references/figure-spec.md`（图表）配套。

读者定位：**零基础大众（小白读者）**——目标是普通大众都能看明白。
页面上每个关键名词都不能裸放：首次出现给白话定义（可加一句类比）；
旁白把页面要点逐条讲透，不赶时间（目标 25–30 分钟）。
每个内容页必须**图文都有**——只有文字或只有图都算不合格；
**每张图都要被讲明白**：页面要点（或图内标注）解释它，旁白再讲透。

## 0. 页面规划（默认 20–24 页，允许 18–26 页；目标 25–30 分钟）

| 页 | kind | 标题 | 图（见 figure-spec） |
|---|---|---|---|
| 1 | cover | 论文中文题目 | 无（封面） |
| 2 | text-left | 一.论文概述 | **论文首页截图 cover.png**（题目/作者/期刊信息，固定必选） |
| 3–4 | text-left | 二.研究背景（可 2 页：领域背景 / 技术现状与矛盾） | 原文背景图/架构图；第 2 页配动机数据 bar |
| 5–6 | text-left | 三.研究问题（可 2 页：核心问题与难点 / 动机示例走一遍） | 原文动机示例图；第 2 页可加传统流程对照图 |
| 7–9 | status | 四.传统研究现状（2–3 页：第 1 页分类总览，其后每类或每两组一页） | 图槽1：方法分类框架图（自绘 framework）；图槽2：对比表（原文 Table 优先） |
| 10–14 | figure-left | 五.本文研究方法（3–5 页：核心原理 + 关键概念解释 + 每个主要机制一页） | 原文总体框架图；机制图/自绘 flow；关键名词配示例图 |
| 15–18 | figure-left | 六.示例说明（2–4 页：第 1 页整体流程，后续逐步推演） | 示例流程图（原文示例图优先；没有则自绘 flow：步骤→输入→输出） |
| 19–22 | figure-left | 七.实验结果（3–4 页：设置与基线 / 主结果 / 消融 / 分析） | 原文主结果图、消融图、分析图 |
| 23 | text-left | 八.总结 | 不足与启发卡片（cards 自绘） |
| 24 | **refs** | **参考文献** | 无（条目列表，见第 9.5 节） |
| 末 | closing | 谢谢聆听 | 无（结束页） |

规则：

- **五.本文研究方法至少 3 页**：第 1 页讲核心原理（为什么能解决之前解决不了的问题），
  第 2 页可做「关键概念解释页」（把方法依赖的 2–3 个前置概念用白话+示意讲清，小白才能跟上），
  后续页讲具体步骤（每页 1–2 个模块/机制），标题都带「五.」前缀。
- **六.示例说明至少 2 页**：第 1 页讲整体思路与流程总览（整图+一句话总览），后续页逐步
  推演、每步讲清与前后步骤的逻辑衔接（详见第 6.5 节）。
- **七.实验结果至少 3 页**：设置与基线 → 主结果 → 消融/分析；图表讲解按 narration-spec
  的五步模板（总体→轴→比对对象→结论→细节）。
- **参考文献页固定 1 页**，放在八.总结之后、紧邻结束页之前（倒数第二页）。
- 同一节连续排布；页数落在 20–24 最佳，论文内容少可降到 18，上限 26（再长就压缩重复内容）。
- status 页（四.）有两个图槽：分类框架图 + 对比表各占一槽。

## 1. 封面（cover）

| 字段 | 内容 |
|---|---|
| title | 论文中文译名（过长可只取主标题）；确无通行译名时用英文原题 |
| subtitle | 「发表于 会议/期刊全称 年份（CCF-x / SCI x区 / 预印本）· 论文总结汇报」；级别与影响力见深读阶段核实的发表信息，拿不准就写预印本，禁止编造 |
| presenter / date | 汇报人 / 日期（用户未给就向用户要，不要猜） |

## 2. 一.论文概述（text-left，1 页）

整页 5–6 个**标题式要点**，按固定顺序，是全文的缩影（注意：全是短语，不是句子）：

```
发表：{{OSDI 2025}}（CCF-A）· 链接 arxiv.org/abs/xxxx
  └ 系统方向顶会 · 录用率约 xx%
背景与问题：PIM 缺{{运行时}}支撑
  └ 引擎按逻辑块动态管 KV 缓存；PIM 只加速注意力计算
方法：{{分层粒度分配}} + 提交区
  └ 逻辑块绑定物理放置与命令 · 不改处理单元
结果：{{1.95×}} 加速 / 4.83× 能效
  └ 对 NeuPIMs 等 4 个基线平均
意义：块级缓存管理{{首次}}落地通用 PIM
```

- 【发表】必须交代：哪年、什么会议/期刊、什么级别、影响力（一两句），
  **并给出论文网址**（`meta.json` 的 `link_candidates` 核实确属本文后写入；
  确无公开链接就写「未找到公开链接」）。网址放发表要点的一级主句或二级行——
  **只放页面，旁白不念**（check_narration 强制）。
- 【方法】要点写「提出 xxx + 核心原理一句话」，方法名必须出现。
- 【结果】带最有分量的 1–2 个数字；【意义】落在一个判断上，不写「意义重大」。
- 总结句：一句话概括本文定位（问题 → 方案 → 效果）。
- 图：**固定用 `extract/cover.png`（论文第 1 页顶部截图）**——读者一眼看到论文原题、
  作者、期刊/会议信息；旁白讲发表信息时指着这张截图讲。不用 cards、不用 teaser。

## 3. 二.研究背景（text-left，1 页）

- 3–4 个要点，**写成一条逻辑链**：大背景（领域趋势）→ 技术现状（现在怎么做）→
  矛盾/需求（什么变了、什么跟不上）→ 由此引出研究问题的重要性。
  不许并列堆背景条目；每条是链条上的一环。
- 内容主要取自论文 Introduction 前半部分。
- 图：论文的背景架构图（如目标平台/系统架构 Figure）。**这页最容易空**：
  原文图偏小时，或补第二组图（原文次要图/动机数据 bar），或用加中文标注的图放大，
  或把要点二级行写满——不许「一张小图 + 三行字 + 一片空白」。
- 总结句：一句话点出「背景 → 缺口」，为下一页研究问题铺垫。

## 4. 三.研究问题（text-left，1 页）

- 3 个要点：
  1. **核心问题**：1–2 句话高度概括本文要解决的学术问题（一句「如何……」的问句或任务句）；
  2. **动机示例/数据**：论文的动机示例（通常有图）或量化动机（如「单 token 写占注意力延迟 30%」）；
  3. **难点**：为什么这个问题难（根本冲突、已有思路的天花板）。
- 图：**原文动机示例图优先**——论文用示例图讲动机的，直接用那张图；
  图中英文术语在要点或图标注里给中文解释。
- 总结句：把核心矛盾再说一遍（可带最关键的一个数字）。

## 5. 四.传统研究现状（status，1 页）

- 3–5 个要点：第 1 条**总起分类**（已有工作分几类——旁白第一句就是「已有研究分为 N 类」），
  其后每类一条：`类别名：原理一句话 → 不足一句话`，**每类必须带原文引用标记**
  （如 `AttAcc [2]`、`NeuPIMs [1]`），编号与论文参考文献一致。
- 2–3 页拆法：第 1 页分类总览（framework 图），后续页每页展开 1–2 类：该类怎么工作
  （原理展开到小白能懂）、面对动机示例怎么失效。
- 结合三.的动机示例说明不足：传统方法面对那个示例会怎样失效（一句）。
- 写法陷阱：不要写成「某人做了某事，仍有不足」。要先说这类方法**怎么做（原理）**，
  再**由原理推出**它缺什么——不足是原理层面的天花板，不是「没做好」。
- 图槽 1：自绘 `framework` 分类框架图（层=类别，条目=代表工作）；
  图槽 2：对比表——论文有相关 Table 就裁剪嵌入（`type: image`），没有则用 `table` 重排
  （维度：动态分配 / 物理映射 / 写效率 / 是否改硬件等，按论文实际对比维度）。

## 6. 五.本文研究方法（figure-left，≥2 页）

**第 1 页：核心原理**

- 3–4 个要点：
  1. **关键洞察**：本文的想法是什么、**为什么从原理上它能解决传统方法解决不了的问题**
     （与四.的不足一一对应——传统方法卡在原理的哪一点，本文换掉了哪一环）；
  2. 2–3 条核心机制（每条：机制名 + 一句话原理 + 化解了哪个冲突）。
- 图：**原文总体框架图**（论文方法章开头通常有 overview 图，直接用）。
- 总结句：一句话说清方法的本质。

**第 2+ 页：步骤/机制（每页 1–2 个模块）**

- 标题格式「五.本文研究方法：模块主题」（如「…：分层粒度分配」「…：提交区机制」）。
- 3–4 个要点：每个模块「做了什么 → 怎么做（关键设计一两句）→ 效果落点（数字）」。
- 图：原文该模块的机制图；论文没有现成流程图时，用 `flow`（steps + children）按原文机制自绘，
  自绘图必须准确反映论文机制，宁可简单不可画错。
- **关键名词配示例图**：页面出现论文的关键名词/机制名（如某数据结构、某调度单元），
  论文里有对应示意/示例图（motivation figure、设计细节小图）就用上去，让名词看图即懂；
  论文没有、而该名词又是理解机制的拦路虎时，可自绘一张小示意放第二图槽。
- **这页不许空**：单机制图偏小或只占半版时，补第二组图（名词示例图、机制小流程、
  重排 table）或把二级行写满；实在没图可补，就加一条解释性要点。
- 总结句：这一页的机制换来什么（带数字最好）。

## 6.5 六.示例说明（figure-left，1–2 页）

方法讲完、实验开讲前，用**一个简单例子把全文核心方法贯穿起来，一步一步推导出结果**。
目的：让听众（尤其小白）在进实验前已经「亲手跑过一遍」方法。

- **取材**：论文自带运行示例/动机示例 → 直接用（原文示例图优先，照实推演）；
  论文没有 → 基于对本文的理解**自构**一个小例子：规模尽量小（几个元素、两三步），
  但必须能走完核心方法的全链条，能突出传统方法做不了、本文方法做得了的那一步。
- **自构口径**：自设数值一律标注「示例取值」（页面标注或旁白口播）；推演逻辑与论文
  机制严格一致，不得为了例子改变方法。
- **第 1 页（整体思路）**：示例设定（输入是什么、多小、为什么选它）+ **整体流程总览**
  （整张流程图 + 一句话把「从输入到结果要经过哪几步」说完）；
- **后续页（逐步推演）**：每页 1–2 步，每步「输入 → 处理 → 输出（数据形态）」，
  **并且必须写衔接句**——这一步的输出如何成为下一步的输入（页面要点写「输出 X →
  作为下一步的输入」，旁白顺着讲）；步骤间有分支/回退也要讲清逻辑关系；
- **收尾**：推演结果（例子跑完得到什么、验证了什么）+（可选）示例中体现的传统方法瓶颈。
- **图：示例流程图**（这页的灵魂）。原文有示例图用原文；没有则自绘 `flow`：
  节点文字写「步骤：输入→输出」，把每步的**输入数据、输出数据、数据存储形式**
  （张量/列表/位图/键值对……）钉进图里；子步骤写进 children。旁白按图逐步推演。
- 示例复杂或论文示例值得展开时拆 2 页：第 1 页设定 + 流程图，第 2 页关键步骤细节
  （或示例结果 vs 真实规模对比）。**最多 2 页**。
- 总结句：示例把方法链条的每一步都落了地（一句话）。

## 7. 七.实验结果（figure-left，≥2 页）

**可选拆页：设置页**（实验多时）——要点写：实验目标（回答哪几个问题）、平台、负载、
基线与指标；图用 `table` 重排设置表或原文平台图。

**主结果页 + 分析页**，每页 3–4 个要点：

- 要点必须覆盖：实验要回答的问题 → 关键设置（平台/负载一两句，设置页已讲则略）→
  结果数字 → **结论与分析**（为什么赢/输在哪儿，收益来源）。
- 数字全部来自原文；倍数/百分比照抄，不四舍五入到别的数。
- 图：**原文实验图表优先**（主结果图、消融图、分析图），`type: image` 嵌入并带
  `caption`（「摘自原文 Figure 7：一句话说明这张图表达什么」）。
- 总结句：这一页图表给出的判断（不是复述数字）。

## 8. 八.总结（text-left，1 页）

用户标了「这点很关键」的页，三类要点缺一不可：

1. **一句话总结**：背景问题 → 本文方法 → 效果数字（对应原文 Conclusion）；
2. **不足与改进**：2–3 条本文局限（评估方式、假设条件、未覆盖场景），每条尽量带
   改进方向（来自原文 Discussion/Future Work；原文没有就基于事实提炼，注明「自析」口径）；
3. **启发**（深挖，关键项）：仔细分析全文后给后续研究的启发，1–3 条，从这些角度找——
   - 前提假设与限制：哪些假设在实际场景可能不成立、放宽后会怎样；
   - 没考虑的因素：负载/规模/硬件变了，方法还成立吗；
   - 换场景：方法搬到邻近问题/领域，哪些设计可复用、哪些要改；
   - 与 xxx 融合：和哪类已有工作结合可能放大收益；
   - 论文未介绍或定死但特别关键的点：某关键步骤没讲清、某超参/阈值写死，
     这些往往就是下一篇工作的入口。
   每条注明口径（原文 Future Work / 自析），落到「可以做什么」，不复述贡献。
   **旁白话术**：第一人称感受式——「通过这次阅读，给我的启发是…」，不许说
   「启发两条/三点/如下」列举式开头（check_narration 强制）。

- 图：`cards` 三张卡（不足 / 改进方向 / 启发），或原文结论性图。
- 总结句：一句话价值判断（这篇工作的历史位置或可借鉴点）。

## 9. 结束页（closing，要点回顾 + 感谢聆听）

- title：默认「要点回顾」；
- summary：一句话 Take-away——本文最重要的结论，核心词用 `{{红粗}}`；
- info：论文出处一行：英文原题 · 会议/期刊 年份（或 arXiv 编号）· 论文网址 · 代码链接（若有）；
- thanks：固定「**感谢聆听**」，居中大字（模板默认，不必另写）；**不写「欢迎批评指正」等套话**。

## 9.5 参考文献页（refs，倒数第二页，固定 1 页）

与 PPT 正文里出现的引用编号一一对应（check_ppt 强制：正文引了 [N] 而本页没有该条 → 错误）。

- content.json 写法：`{"kind": "refs", "title": "参考文献", "refs": ["[7] ...", "[21] ..."]}`；
  条目必须以 `[N]` 开头，**只列 PPT 里引用过的编号**，最多 10 条（超了就压缩正文引用面）。
- 条目内容从论文 References 列表照抄并压缩：`[N] 作者. 系统/题目. 会议/期刊 年份`，
  作者多取一作 + et al.；编号保持与论文一致，**不要重新编号**。
- 版面由 build 自动排：无图槽、正文拉通全宽、字号 12–14 磅自适应。
- 本页不要求图文都有、红粗、总结句；旁白固定一句「下面是论文的相关参考文献，
  感兴趣的可以按图索骥」之类（≤2 句、≤120 字），**不逐条念、不说别的**
  （check_narration 强制）。
- 图表引用（Figure/Table 编号）不用进本页——本页只对 [N] 文献引用。

## 10. 全局硬规则（写作形式）


- **标题式要点，杜绝大段文字**（参照 proposalword2ppt 的写作形式）：
  - 一级：`标签：短语主句`，主句 ≤20 字宽（现状页带引用放宽到 24），**不许出现句号**；
  - 二级：短说明（数字落点/机制补充），≤22 字宽，一条一级下最多 3 条；
  - 连标签、二级在内**层级不超过 2 级**（≤3 级的上限内）；
  - 完整的句子、因果论述全部放旁白讲，页面上只留短语。
- **正文版式**（build_ppt 自动排，写 content.json 不用管，但要知道效果）：
  一级 `▶` 18 磅、二级 `●` 16 磅（小 2 号）；二级文字比一级再进 2 个字；
  下划线只给标签（含冒号），主句与二级行不带。**文字字体字号固定不自适应**，
  放不下按「减字数 → 砍二级行」处理，不压字号。
- **红粗强调**：`{{重点}}` 渲染为红色（C00000）加粗，`**粗体**` 渲染为加粗；
  每个内容页**至少 1 处 `{{}}`**，用在关键数字、方法名、结论词上；每页 1–4 处，满页红等于没红。
- **图文互释**（每张图都要让读者看明白）：
  - 旁白必须讲这张图：是什么、怎么看（横纵轴/颜色/分组）、说明什么——
    只放图不解释算不合格（check_ppt 强制）；
  - 页面要点中至少一条与图相关：解释图中关键元素、英文术语的中文含义或图的结论；
  - 图中英文术语多、结构复杂时，用 PIL 在复制件上叠中文标注（圈注、箭头+术语翻译、
    关键结论短句），存 `figN_annotated.png` 嵌入（见 figure-spec）；
  - 原文图 caption 格式「摘自原文 Figure N：一句话说明这张图表达什么」；
  - **figure 结构化字段**（给视频端指图与图表讲解用，content.json 的 figure 对象）：
    - `ref`：原文编号（如 `"Figure 15"`、`"Table 3"`）——旁白说「图 15」靠它精确对图；
    - `brief`：一句话说这张图总体干什么（如「对比 4 种方法在不同批量下的端到端时延」）；
    - `axes`：轴与图例说明（横轴是什么、纵轴是什么、每种颜色/每组代表什么、指标
      越大越好还是越小越好）。自绘图（flow/cards/table）同样要写 brief/axes（轴栏写结构说明）。
    三字段写进旁白与页面要点时必须口径一致；check_ppt 逐步接入校验。
- **页面饱满**（版面不许一片空）：
  - 每个内容页 4–6 个要点为宜（下限仍是 3），二级行用满；
  - 单张原图偏小/偏扁时给第二组图——原文次要图、重排 table、自绘 bar/flow 均可；
    单图槽版式给 2~3 组图会自动上下切分图槽（如「动机示例图 + 开销图」「主结果图 + 设置表」）；
  - 上下切分后每格约 18.2 × 4.5 cm，图按长宽比自适应；表格每列文字要短（一列一词），
    否则图内文字截断校验会报。
- 每个内容页：3–6 个要点（check_ppt 卡 ≥3），图文都有，总结句非空（status 页除外）。
- 标题用「一.」「二.」等前缀，同节多页时标题主题不同（如「五.…：核心原理」「五.…：提交区」）。
- **概念解释硬规则**：论文的关键名词/机制名（方法名、核心数据结构、关键指标）
  首次出现的那一页，页面要点或旁白必须给白话定义；定义要「术语 = 大白话（+ 类比）」，
  让零基础读者接得住。拿不准小白懂不懂就当不懂。这由审核 agent 逐页核对。
- 所有数字、机制描述、引用编号来自论文原文；换算值写明依据；示例说明页自构数值
  标注「示例取值」。
- **旁白不念网址/DOI**（页面要点上放网址即可，解说词禁止出现 URL、arXiv 编号朗读、
  DOI 字符串）——check_narration 强制。
- **颜色表述完整**：说「红色区域/蓝色柱/橙色部分」，禁止「红是/橙是/绿代表」这种
  省略「色」的说法——check_narration 强制。
- **说人话**：旁白是讲解稿不是提纲串词，句子要完整顺口（主谓宾齐全），不为了
  精简字数牺牲通顺；写完必须通读一遍再交审核。
- 自绘图**不加「自绘」标识**；不写「创新点」「具有创新性」「意义重大」这类空话，用事实短语。
