# 图表选型与备图规范

论文总结 PPT 的图**以论文原图为主**——读者要能对着原文核对；论文没有的才自绘。
每页的图必须服务本页主题，**禁止把其他章节的图挪过来用**。

## 1. 选图顺序（对每个图槽依次判断）

1. **原文有现成图 → 直接用**：`extract/figures/` 里的裁剪 PNG（fig/tab 前缀）。
   把要用的复制到工作目录 `figs/`，在 `content.json` 里写 `"figs/fig5.png"` 或
   `{"type": "image", "path": "figs/fig5.png", "caption": "摘自原文 Figure 5"}`。
   嵌入时脚本会**自动裁掉图的近白边缘**，并**按图自身比例在图槽内放大到贴边**
   （宽图占满槽宽、高图占满槽高，不再垫白底画布）——所以只需关心图本身内容是否清楚。
2. **原图太小/只是表格截图 → 按原结构重排**：表格行数 ≤5 时用 `table` 重排
   （数字逐个照抄原文，不许改）；表格太宽就删次要列，保维度列 + 本文相关列。
3. **原文没有 → 自绘**：分类用 `framework`，流程用 `flow`，因果链用 `logic`，
   不足/启发用 `cards`，对比用 `compare`/`table`。自绘图必须准确反映论文机制，
   宁可简单不可画错。

## 2. 清晰度判据（用原图前必查）

图槽 18.16 × 9.27 cm（7.15 × 3.65 in），`figures.json` 里有每张图的像素宽与宽高比。
按**实际放置尺寸**折算有效 DPI（图按宽高比放入槽内，不一定铺满槽宽）：

```
放置宽(in) = min(7.15, 3.65 × 宽高比)
有效 DPI   = 像素宽 ÷ 放置宽
```

- **≥110**：直接嵌；
- **95–110**：可用但投影偏软，须在生成说明里注明；曲线图可考虑改用关键数字重排；
- **<95**：不要硬嵌。看是不是裁剪失败（`crop: null` 的兜底整页图必须人工确认范围），
  换原文放大版，或按原结构重排（表格）/重画（机制图）；实验图可用文中明确给出的
  数字重排成 bar（数字照抄，不许从图上目测估值）。

`extract_pdf.py` 的裁剪是 200 dpi，通栏图直接够用；单栏小图常落在 95–110。

## 3. 各节配图（与 content-spec 第 0 节对应）

| 节 | 首选 | 原文没有时 |
|---|---|---|
| 一.概述 | 发表信息卡（cards）或论文 teaser 图 | cards：方向/定位/贡献 |
| 二.背景 | 原文背景/架构图（常为 Figure 1） | logic 因果链 |
| 三.问题 | **原文动机示例图**（点名要用） | 把动机数据排成 bar |
| 四.现状 | 图槽1 framework 分类图；图槽2 原文对比 Table | 对比表用 table 重排（维度照论文） |
| 五.原理页 | **原文总体框架图**（点名要用） | framework 按方法模块分层 |
| 五.步骤页 | 原文该模块机制图 | flow（steps 带 children 讲子步骤） |
| 六.实验页 | **原文主结果图/消融图**（点名要用） | 关键数字用 bar 重排（数字照抄） |
| 七.总结 | cards（不足/改进/启发） | — |

## 4. 自绘图 spec 速查（shapes.py 实测键名，写错会画出空框）

```jsonc
// 分类框架：层=类别。最多 4 层、每层条目 ≤4
{"type": "framework", "title": "已有方法分类", "layers": [
  {"name": "静态映射", "items": ["AttAcc", "CENT", "PAISE"]},
  {"name": "动态分配", "items": ["NeuPIMs", "PIMphony"]}]}

// 流程：最多 5 步，children 是子步骤（≤3 条）；desc 是一句话说明
{"type": "flow", "title": "Value 写路径", "steps": [
  {"label": "新 token 生成", "desc": "解码阶段单 token 写"},
  {"label": "写入提交区", "children": ["条带化槽位", "每通道一次行激活"]},
  {"label": "满块提交", "desc": "第 16 个 token 后整块搬入"}]}

// 卡片：最多 4 张，title 是卡片名，lines 是正文行（≤3）
{"type": "cards", "items": [
  {"title": "不足", "lines": ["缺真实硬件验证"]},
  {"title": "启发", "lines": ["运行时翻译层思路可迁移"]}]}

// 表格：columns 表头，rows 最多 5 行；数字照抄原文
{"type": "table", "title": "支持情况对比", "columns": ["系统", "动态分配", "物理映射"],
 "rows": [["NeuPIMs", "是", "否"], ["PATTON", "是", "是"]]}

// 因果链（背景页原文没图时用）：nodes 最多 4 个，按从左到右
{"type": "logic", "title": "背景逻辑链", "nodes": [
  {"label": "LLM 生产部署"}, {"label": "KV 缓存块级管理"},
  {"label": "PIM 只加速计算"}, {"label": "运行时缺口"}], "foot": "缺口即研究问题"}

// 柱状（重排关键数字时用）：items ≤6；末尾 0 不许丢（30.30），用 text 指定精确写法
{"type": "bar", "title": "相对基线加速比", "unit": "倍",
 "items": [{"label": "NeuPIMs", "value": 4.27}, {"label": "PIMphony", "value": 1.42},
           {"label": "命中率", "value": 30.3, "text": "30.30%"}]}
```

注意：`cards` 的键是 `title`/`lines`（不是 label/text）；
`flow` 的键是 `label`/`desc`/`children`（不是 nodes/edges）；
`table` 的键是 `columns`/`rows`。标题 `title` 可省（省了把高度让给图）。

## 5. 通用要求

- 图内文字 14–18 磅（脚本自适应）；相邻节点空隙 ≥0.7 cm，箭头不贴框。
- 配色只用模板主题色（shapes.py 自动）；不引入截图花边、不加与主题无关的装饰。
- 原图表必须带来源：`caption` 写「摘自原文 Figure 7 / Table 2」；
  重排/自绘在生成说明里注明「按原文 Table 1 重排 / 自绘」。
- 每张图只取本页对应章节的事实；一页只讲一件事。
- 现状页两槽：framework + table 各一，不要两槽都塞表格。
- **补图饱满**：单图偏小、版面空时给第二组图（原文次要图 / 重排 table / 自绘 bar）。
  单图槽版式给 2~3 组图会自动上下切分（每格约 18.2 × 4.5 cm）；
  切分格较矮，第二组图选扁宽的（原文双联图、两列表），表格单元格一列一词防截断。
