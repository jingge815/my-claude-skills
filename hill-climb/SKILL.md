# 持续指标优化（hill-climb）工具

围绕一个可测指标做多轮受控实验：核心纪律是测量可信（冻结 harness）、变量单一（一次一改）、可回退（不过线整体 revert）、决策留痕（decision.tsv）。适用于 tune/、CycleEstimation.csv、ir_cost.py cycle 估算这类"围绕一个数字持续改进"的场景。

## 不可违背的原则

1. **先冻结测量 harness，并证明它灵敏。** harness（一条命令、固定负载、中位数采样、自带错误数与工作量计数）建立后，用对比性负载验证它能区分"已知更差/更好"的两种实现，再按 `pstack/benchmark-checklist`（Read `~/.claude/skills/pstack/benchmark-checklist/SKILL.md` 并遵循）核验后冻结。冻结后不许为让某个结果好看而改 harness；要改就解冻、重证灵敏度、重记 baseline。
2. **baseline 与回归门先行。** 第一个改动之前：记录 baseline 指标（中位数+范围）、跑绿一遍回归门（必须保持通过的测试/对齐命令，来自项目 CLAUDE.md 验证命令清单）。
3. **一次一改一测。** 每轮只验证一个假设；假设必须点名具体机制（"把 X 移出热路径，因为它每元素同步调用 Y"），不接受"试试 memoize"。多个想法独立时可以准备多轮依次验证，但每轮只落一个改动。
4. **保留判据刚性。** 指标改善超过噪声线且回归门全绿才保留，否则完整回退该改动；"可能有用"的搭车改动一律回退。每个保留的优化单独一个 commit（只 add 自己改的文件，不用 `git add -A`）。
5. **停止谓词先定且不放松。** 谓词形状 = 目标 + 最小轮数下限（例如"至少比 baseline 好 50%，且至少跑满 10 轮"），用户给了数字就用用户的。满足谓词、或剩余想法已边际化（收益不值成本）才停；不许放松谓词宣布胜利，也不许便宜想法没试完就停。
6. **每轮一行 decision.tsv。** 按 `pstack/show-me-your-work`（Read `~/.claude/skills/pstack/show-me-your-work/SKILL.md` 并遵循）在任务 docs 目录的 decisions.tsv 追加：假设、改动、before、after、delta、回归门结果、判定（保留/回退）。append-only，错了补行不改历史。
7. **正确性与简单性优先于数字。** 破坏行为的"赢"必须回退；保住数字的简化可以保留。串行执行为默认（一次一改一测本就串行），不引入并行实验。

## 标准工作流程

### 阶段一：定指标与停止谓词

- 梳理工作负载与架构，选一个能复现真实抱怨的负载案例（复现不了先修复现，不进 hillclimb）；固定一个指标、明确"更好"的方向、写下停止谓词（目标+最小轮数）。

### 阶段二：建 harness 并冻结

- 实现测量 harness：单命令、固定负载与采样数（中位数，非单次）、输出指标+错误数+工作量计数。
- 灵敏度验证：跑一个已知更差与一个已知更好的变体，确认 harness 能区分；过 benchmark-checklist 七问；记录 baseline 与回归门绿跑证据；冻结。

### 阶段三：假设循环

- 从架构模型出发列假设清单，按性价比排序。
- 每轮：落一个改动（可委托子代理，模型按 `dev-flow/config.toml` 的 worker.code；主对话审 diff）→ 冻结 harness 前后测 → 回归门 → 判定保留或完整回退 → commit（保留时）→ decision.tsv 记一行。

### 阶段四：跨越平台期与收尾

- 连续多轮被拒时换假设类别、合并近 misses、重读源码、或试更激进的方案，再考虑"山已爬完"。
- 停止后报告：指标与目标、baseline→final 及百分比、轮数（保留/回退）、每个保留优化一行、decision.tsv 路径、若继续推进的下一个最佳想法。
- 结果回到质量闭环：保留的改动累计走 code-review-doc / review-fix-loop 评审。

## 实操要点

- **多轮拒绝是信息**：连续回退说明架构模型有盲区，回头重读 trace 与源码，不是换个随机想法继续撞。
- **数值对齐类指标的回归门要包含对齐断言**（与参考实现的逐元素对比），不是只跑功能测试。
- **harness 的错误数计数免费帮你做七问第 4、7 问**：错误数不为零或工作量计数异常的轮次，数字作废。
- **不叠加未验证改动**：两个想法都想要时，分两轮各自验证后，第三轮验证组合（组合也算一次改动）。
